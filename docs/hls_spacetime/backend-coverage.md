# Vivado and openXC7 viewer coverage

Both workflows attach physical evidence to recorded writes. The viewer also reads historical Vivado publications identified by source, RTL, observation and their routed checkpoint. A modern implementation identity must match on every participating attachment. The comparison unit is the same logical write, destination bit and data, enable or reset role. Each implementation owns its placements, pin names, routes and delay model. The [native workflow](native.md) gives the capture and join commands.

| What the user can inspect | Vivado | openXC7 | What would close the gap |
| --- | --- | --- | --- |
| Execution and placement | Events, versions, dependencies and checkpoint cells at site/BEL/tile resolution | Same execution model and packed cell placement, including site-internal and tile-owned BELs | On a matched application, count all logical target bits, qualified bits and placed backing cells. Preserve ambiguous and optimized-away cases. |
| Which storage bit was written | Finite correspondence checks for FDRE, FDSE, FDCE and FDPE, with exact native Q connectivity | Explicit RTL word and configuration-qualified rising-edge FDRE D/Q, clock, enable, reset and initialization | Consume producer word declarations from the actual RTL build. Add other FF configurations in order of observed frequency, each with a reset/enable/initial-state witness and a negative binding case. |
| Logic between registers | LUT, CARRY4/8 and dedicated MUXF timing arcs from SDF | Ordinary packed LUTs including fractured/permuted inputs. SRL and distributed-RAM modes sharing a LUT BEL stop traversal. Carry, dedicated mux and I/O boundaries can also end a cone. | Qualify the packed XC7 carry and mux pin dependencies against native arcs. Distinguish an external input launch from a missing I/O model. Compare data and control coverage separately. |
| A net branch | The exporter can request every canonical net and endpoint from a saved checkpoint. Some site geometry stays unresolved. | Selected nets or an opt-in whole packed-net census within the capture budget, with directed PIPs and BEL-pin wires including site routing | At decoder scale, derive bounded route demand and collect it against one frozen implementation. Count distinct requested branches, exported nets and resolved endpoints separately. Keep unselected, unavailable and ambiguous routes visible. |
| A delay through a write | Fast and slow STA SDF, with per-corner arc evidence | One nextpnr estimate per modeled arc. Sink estimates can be routed, predicted or unavailable. Multiple corners require independently supported models for that part and speed grade. |

| Worst constrained path, clock and slack | Saved STA paths can carry ordered points, clocks, requirement, slack and a cross-reference to a selected sink | No structured openXC7 STA path attachment. ## Evidence for sizing the campaign

The executable Z-7030 witness has eight clock edges, two bound register bits and 35 modeled delay queries checked against nextpnr’s independent SDF writer within 1 ps. In the captured write at edge 2 the register-launched data bound is 1.295 ns. Enable and reset reach input buffers outside qualified cone traversal. At that write, capturing both data nets resolves 2 of 12 distinct net branches. Capturing all 15 packed nets resolves 8 of 12, including both enable and both reset branches. The remaining four connect ground or Q feedback to permuted inputs on the two LUT halves. The post-route BEL-pin wires are absent from those nets’ bound-wire sets. Check nextpnr’s permutation PIPs and post-route pin rewriting before qualifying these endpoints. The two chip-wide constant nodes alone contributed 85,272 tile-wire records, out of 86,160 total route objects. [Fixture and checks](../../apps/hls_spacetime/test/native/openxc7/run_witness.sh)

The archived Vivado repetition N2 gallery opens in the current viewer with its prepared arrival layout. Its selected D pin shows 8.815 ns across 83 SDF arcs, and its optional regional view loads 289,074 distinct PIPs. The six-actor publication has 61,764 events, 7,637 writes and 23,292 nets on an UltraScale+ XCZU7EV. It located 864,509 of 1,090,260 target-bit occurrences. Of 92,683 native net arcs, 49,693 resolved fully. These are the reference denominators for assessing a new run. Its 361 CARRY8s and the XC7 CARRY4s below reflect different physical implementations. [Repetition workload](../../yap/hls_spacetime/spacetime-case-1.md) · [Vivado coverage and dispositions](../../yap/hls_spacetime/spacetime-computation-routes-1.md)

The XC7 synthesis-only N2 preflight used the six files in the Vivado archive’s `native-1/files.f`, each checked against `native-1/plan.json`. With its existing BUFG and out-of-context boundary, Yosys produced 30,222 primitive cells plus nine scope metadata records. The result has 8,827 FDREs, 590 CARRY4s, 1,690 MUXF7s and 557 MUXF8s. It contains no BRAM, SRL or DSP. The selected synthesis JSON is 32,001,723 bytes. A Z-7030 pack-only probe with the timing observer hit the 100,000-object limit while collecting pre-pack origins. A second pack-only probe without the observer reached I/O insertion. The retained Vivado top exposes 177 bits. The XC7 packer reported 150 available pins for that unconstrained boundary. Neither probe reached placement.

Reproduce the preflight from `spacetime-2026-11-06/physical-1/reproduction.tar.gz` in the project artifact archive. From its `native-1/` directory, read the six SystemVerilog files in list order, then use Yosys `synth_xilinx -family xc7 -flatten -noiopad -noclkbuf -top spacetime_native_top`, select `spacetime_native_top` and write the selected JSON. The measured Yosys revision was `66306a8ca-dirty` in the Apio OSS CAD Suite. Run the pinned observer with the Z-7030 chipdb, that JSON, `--pack-only --spacetime-timing pack-probe.json --spacetime-objects 100000`. Repeat on the matching baseline binary with the same chipdb and JSON and only `--pack-only --write baseline-packed.json`. The caps were 300 s for synthesis, 120 s per probe and 6 GiB process-group RSS. The G4 evidence directory is `runs/spacetime-g4-parity-2026-11-24/`.

The separate four-Phi Z-7030 audit found ignored native timing ports on all 52 BRAMs. In its Vivado reference, the worst setup path at the 100 MHz request started at a BRAM and crossed arithmetic into an executor register, with 17.657 ns of data delay. This is evidence of a missing path class. Native and Vivado placements differ. The retained report is `experiments/07-openxc7/results/native-timing-coverage-2026-09-24.md`. ## Qualification order

The master roadmap owns campaign G4.4. The N2 source closure and synthesis census are established. The remaining work starts with the pre-pack provenance limit and I/O boundary.

1. **Make one representative recording capturable.** Use `phi_protocol_config:repetition(2, #{})` and the retained stimulus and public completion oracle, including the correction in step 4 between C(3) and C(4). Record exact top, all RTL files, RAM/support modules, clock constraints and observations. The current openXC7 exporter accepts one self-contained `top`. Support the verified ordered source list and top. Use a qualified out-of-context boundary or a pin-fitting wrapper that preserves streams and fault/status observability. Replay the public oracle and identify any logic pruned by the wrapper. Separate pre-pack origin collection from the post-route query budget. Limit detailed provenance to needed words and combinational dependencies, or stream a budgeted whole-design index. Record what the selection excludes. Reuse the saved Vivado reference for feature coverage and declare its different part. A physical timing comparison needs matched device, grade, constraints and boundary conditions. Keep each trace join bound to its own implementation.
2. **Publish a coverage ledger for both runs.** Use the synthesis counts above and make one bounded capture of the selected interval. Report mapped/requested target-bit occurrences, writes with zero/partial/full mapping, known/unknown/out-of-scope cones by role, distinct required/resolved driver-to-sink branches, delay-query dispositions and unsupported primitive/port counts. Separate unique objects from repeated writes. Retain the identity, limits and reason for any failed stage. Use a selected-cone pilot if whole-design caps are exceeded and label its denominator. Escalate export size only with measured byte, RSS, run-time and browser-load budgets.
3. **Close the largest viewer-side losses.** Measure how many selected bits stop at each carry, dedicated mux, I/O or permuted LUT pin, then qualify the dominant case. Publish native route demand and prepared render parts with independent hashes and finite caps. Replay the same interval and compare coverage before/after. Require equivalent logical event selection, stable registered data bounds, exact route endpoints and visible missing-evidence cases. Verify the existing Vivado publication through the same controls.
4. **Qualify native STA and hard boundaries separately.** Use a reconvergent two-path case to check exact path selection, ordered points, arrivals, requirements and any reported slack. Use the four-Phi BRAM-to-arithmetic case for the first material backend model gap. Compare endpoints and configuration before comparing timing values. An unsupported clock relationship or hard-block mode must stop the relevant timing claim.
5. **Repeat the representative run.** Report both implementations’ coverage ledger, the selected write and the worst eligible native path, with links to reproducible captures. A viewer feature can be complete with different numeric estimates. A missing path class remains an explicit exception to whole-design timing. Run fresh Vivado only if the retained evidence cannot answer the remaining comparison.
