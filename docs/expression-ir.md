# Expression IR

Clause lowering retains add/sub/xor and integer-comparison nodes until `xls_clause_lower:print/1` renders DSLX. `xls_expr_ir` records those definitions and binding aliases within each clause or branch. Opaque calls, casts, textual leaves and branch joins supply no arithmetic definition; generated text is never parsed back into operations.

This extends the existing clause IR. Source classification identifies integer comparisons, while DSLX still enforces arithmetic widths and signedness. Other expression kinds may remain opaque DSLX leaves. Original statements, evaluation order and eager failure checks are preserved. The representation introduces no optimization pass or compiler option. Algebraic bit-vector simplifications belong to XLS, where operand types and node identities are available.

`xls_dslx` retains the structural syntax used around these values: references, field/index/slice access, typed literals, calls, tuple/struct construction, operators, lexical bindings, blocks and selection. It accepts existing clause leaves so type-provider codecs can retain their own checked representation. It is a syntax tree, not a second source-language type system or an optimization pass. Its renderer preserves field/argument order and groups operands without parsing source text.

Entry lowering keeps this tree in each artifact's `evaluation` outcome. Its branch-local statements, failure selection, effect packing and `EntryOutcome` constructors remain inspectable until `xls_actor_codegen:emit/3`. Case/if joins likewise keep their selected branches structured; joining a value does not make either branch's scalar definition an unconditional alias. Existing initialization, dispatch and helper artifacts can still contain rendered leaves.

`rebar3 eunit` checks structured lowering, alias resolution, opaque boundaries, rendering, retained entry constructors and eager failure preservation. `tools/test_entry_outcomes.sh /path/to/xls` checks selected entry data/effects/failures against the finite BEAM oracle and exercises provider codecs through DSLX/JIT and RTL witnesses. `tools/test_comparisons.sh /path/to/xls` exercises the existing mixed-width comparison semantics through BEAM, DSLX, JIT and RTL simulation; these executions are witnesses, not universal equivalence proofs.
