# Automatic control simplification

Ordinary compilation automatically simplifies integer equality or inequality between `x` and `x+y`, `x-y`, or `x bxor y` to the same comparison of `y` with zero. Addition and xor allow either operand order; subtraction only cancels its left operand. This is an exact identity for the backend’s same-width, wrapping integer arithmetic. No compiler option or separate file-rewriting step is required.

The clause IR retains add/sub/xor and integer-comparison nodes, plus clause-local binding identities. `xls_ir_control:simplify/2` consumes those nodes before `xls_parse:print/1` renders DSLX. Aliases retain provenance; opaque calls, casts, textual leaves and branch joins do not supply arithmetic facts. The pass does not parse generated text. Original arithmetic statements and eager failure checks remain in place, including when another consumer uses the full arithmetic result.

This extends the existing clause IR, not the complete type system: source classification distinguishes integer comparisons, while DSLX still enforces arithmetic widths and signedness. Other expression kinds remain opaque rendered leaves. The compiler retains the original arithmetic constraints even when a comparison no longer depends on its result.

Exact simplifications run automatically when their structural preconditions hold. Circuit-topology choices such as prefix-carry grouping need target/cost context and belong at XLS’s bit-vector optimization/lowering boundary; they are not frontend flags. This simplification makes no promise of improved physical timing or area.

Run `rebar3 eunit` for lowering, alias, branch-boundary and eager-failure regressions. Then run `python3 tools/test_ir_control.py /path/to/xls --stage /fresh/output --yosys /path/to/yosys`. It compares source-lowered circuits with explicit reference circuits for all binary inputs at widths 1, 2, 8, 12, 32, 64 and 699, signed and unsigned add/sub/xor, eq/ne in both comparison orders, and the complete arithmetic result. A deliberately wrong predicate must produce a counterexample. Logs and source/tool/BEAM hashes are retained. These finite combinational proofs trust frontend lowering, DSLX typing, XLS optimization/code generation, Yosys translation and SAT; they are not an all-width theorem or a sequential proof.
