# Inspecting a saved capture

The viewer reads `spacetime-view` JSON projections. A projection retains the complete event/version graph and unique placed-cell/binding tables, plus independently recorded public annotations, optional ordered static timing paths and selected native routing topology, evidence scope and content identities. Large native property/SDF tables remain in the source archive. Complete computation publications also retain the native pin/net graph; their prepared rendering derivative lets the browser draw circuits without loading that whole graph. A projection is a browsing index, not a replacement evidence archive or a new measurement.

## Prepare and open

Use Node 22 or later and a browser with WebGL 2. No npm installation or external service is required. For a producer-validated bundle:

```sh
node scripts/prepare-view.mjs --bundle /path/to/bundle.json --output /path/to/fresh-view
npm start -- --data /path/to/fresh-view
```

For a [complete computation publication](computation-routing.md), prepare its rendering indexes once:

```sh
node scripts/prepare-render.mjs \
  --input /path/to/computation-publication \
  --output /path/to/fresh-render-view
npm start -- --data /path/to/fresh-render-view
```

Add `--capture RECORDING_FILE` when the input index contains several computation captures. Preparation verifies the recording and source tables, retains their exact bytes alongside the derivative, and writes a new hash-bound index. It never invokes simulation, Vivado or a new timing measurement. Retained source files may be hard-linked; do not edit either publication in place. Original manifests are trusted inventories, not cryptographic attestations of a measurement. `prepare-example.mjs` remains an adapter for retained S3/S4 demonstration archives and qualified extensions, rather than the entry point for new workloads.

The read-only loopback server exposes the viewer and the explicitly selected data directory, accepts no uploads, and uses port 4173 by default (`--port` or `PORT` overrides it). Open the printed URL. The browser verifies capture bytes against the local index. **Open file** accepts a user-supplied projection and labels its provenance as not freshly verified; it cannot discover companion computation files on disk. File content stays local. Use Ctrl-C to stop the server.

## Navigate the scene

The main view is a depth-tested 3D scene of opaque prisms and cubes. Routing connectivity is drawn within clock layers or at illustrative arrival heights; storage links connect layers. Known ordinary propagation is solid in the arrival layout. An explicit schematic endpoint bridge has a thin continuous core and a dashed sleeve, preserving visual continuity while marking incomplete native route geometry. The flat layout keeps its original dashed routing chords. None of these line styles establishes a measured metal trajectory. Objects nearer the camera occlude objects behind them. Their widths and glyph sizes aid legibility; they are not physical metal widths or cell dimensions.

- Drag to **Orbit**; Shift-drag, middle-drag or choose **Pan** to move the view. Scroll or use **+ / −** to zoom. With the canvas focused, arrow keys orbit, Shift-arrow pans, and +/− zooms.
- **3D**, **Top** and **Side** restore useful directions. **Reset view** frames the visible clock window; **Fit selection** frames selected work. Time follows the clock axis, so arbitrary rotation need not leave it pointing down the screen.
- **First clock**, **Window** and the timeline choose the displayed interval. **Layer spacing** changes separation without changing the clocks. A narrower window also reduces drawing work.
- **Expand scene** gives the drawing the full window. **Evidence inspector** opens the selection's provenance and dependency controls; **Chip & resources** opens the optional flat view. Both start closed. **Layers, storage & timing filters** contains the less frequently used controls.
- **Detail** starts at **Routing connectivity**. **Occupied tiles** groups the footprint into small occupied grid bins without connecting spans; separated regions and clocks stay separate, but a bin centre is not a native position; **Connectivity + switches** adds routing-switch markers. These are display choices over the same retained evidence, not population cuts.
- **Dim context** mutes unselected event context while preserving the selected trace; in the function-color style it also mutes background storage. Other styles preserve their storage hue or direction gradient. Geometry remains opaque and depth-tested; this is not transparency or an X-ray mode. **Show unmapped participants** and installed-cell context start off for physical captures and remain available explicitly.

The recording is parsed and indexed in a worker and becomes interactive before circuit loading finishes. Prepared publications load a hash-checked rendering derivative in a worker; full native source records remain separately retained. **Loading details** shows the separate browser stages, including first-frame timings. Preparation time, transfer size and browser latency are different measurements.

## Arrival-time height

Algorithm-4 prepared captures open with latest-static-arrival height enabled over an initial three-clock window; increase **Window** to show more clocks without an event or geometry cap. The flat clock-layer layout remains available for comparison. Each pin's height represents its conservative latest arrival relative to the current Q sources. It is not the time that this recording's values switched, and a held Q value need not have changed at the reference edge.

The recorder samples old Q, D and enables at C before applying rising edge C. The arrival view uses plane `B_C` as the relative launch reference for that old Q and `B_(C+1)` as the capture boundary for write C and the next Q sample. A pin with arrival `a` nanoseconds is displayed at `C + a / budget`. Write glyphs move to C+1 in this view; their saved cycle and inspector timestamp remain C. Other event glyphs retain their cycle anchors rather than acquiring invented subcycle times.

One common **hypothetical budget** sets the spacing between capture boundaries, initially 10 ns. It is a display reference, not a measured clock period. Lowering it to 5 ns can expose arrivals beyond the next boundary; the view does not clamp them or rescale individual cones to make them fit. A known arrival at or below the budget is ready with margin `budget − arrival`; an overrun has negative margin. These dispositions exclude clock-to-Q, setup, skew, constraints and timing exceptions, so they do not qualify a device's timing or supply STA slack. Unknown or inapplicable arrival has no numeric height and remains explicitly unresolved.

At reconvergence the latest input controls the downstream bound. Propagation ends at the source's arrival plus the arc's local delay; a separate readiness link reaches the sink's latest arrival when another input arrives later. This gap is not a register, buffer or attributed wait; only recorded storage histories establish storage. Intermediate net heights interpolate each source-to-sink connection's total SDF cost along its continuous, resolved, ordered schematic chords. This is a display convention, not per-wire delay evidence: shared fanout prefixes can consequently have different illustrative heights for different sinks.

When a native route is partial, discontinuous or unavailable, the arrival layout can instead connect its native pin endpoints at their retained tile coordinates with a direct schematic endpoint chord, provided both XY positions and the source arrival, local delay and target arrival are known. Its thin continuous core preserves the timing connection; its dashed sleeve marks the substituted geometry. The chord ends at source arrival plus local delay, followed by any separate readiness link. Its intermediate positions and heights are illustrative, not recovered wire locations or per-wire delays. Native route dispositions and gap counts remain unchanged; the flat layout retains the original routing geometry. Missing timing stays on the unresolved shelf where coordinates permit, and missing coordinates remain unlocated. No metal bends, Manhattan route or missing timing are invented. These display choices leave all saved native data unchanged and require no new capture or native run.

First/carry-in roots gain no earlier producer. Reset incarnations still sever ancestry, and a final write without a following Q sample gains no confirmed transfer bridge. RAM response latency remains a separate recorded clock relationship; an untimed or unmapped RAM is not assigned an internal arrival trajectory.

## Extend a saved view

A qualified observation extension can add transfer, publication and selected scalar-operand ancestry while reusing the original physical view:

```sh
node scripts/prepare-example.mjs \
  --capture-extension EXTENSION_DIR \
  --base-projection BASE_PROJECTION_JSON \
  --output web/data
```

Replace the two uppercase placeholders with the retained extension directory and qualified base JSON file. Keep the base in a separate directory with its original `index.json` and sibling example files. The extension directory must contain a manifest, `review.json`, `public.json`, and exactly one of `bundle.json` or `bundle.json.gz`.

This mode verifies the base projection's exact digest and the extension files' manifest lengths and digests. It requires a review of complete original-tap and public-field equality, unchanged source/RTL and simulator identities, matching capture bounds/reset incarnations, and the original physical checkpoint. It independently checks unchanged graph records and any narrowly permitted ancestry refinements against an exact review inventory; old relations remain present. The review is a trusted local evidence inventory; the command does not rerun the comparison or simulation. Original physical correspondence and timing retain explicit provenance, added resources remain unmapped, and old event-coverage counts are not reused for the enlarged graph. Verified sibling examples are copied unchanged and the output index is refreshed. No native tool or original report reader runs.

A new interpretation may include `review.graph_refinements`, an array of `{table, id, before_sha256, after_sha256}` entries. `table` is `events`, `versions` or `resources`; digests cover that entire record before and after the change. Use exported `graphRecordSha256(record)` from `scripts/prepare-example.mjs`: it hashes UTF-8 JSON with recursively sorted object keys and preserved array order. Every changed old record needs exactly one matching entry. Duplicate, unlisted, unused or mismatched entries reject the extension. Omitting the inventory retains the additive-only contract.

The permitted changes are deliberately narrow:

- An event may add `inputs` or `outputs` and update nonempty `evidence`. Existing input/output identities remain present; event identity, clocks, observer sequence, actor context, operation, access and resources remain unchanged.
- A version whose original `producer` is `root`, `origin` is `unknown` and `storage` is `null` may acquire an event producer and nonempty evidence in the same incarnation. Its identity and all other fields stay fixed, including `storage: null`. Stored words and initial/reset origins cannot be refined this way. Normal graph validation still rejects backward dependencies, cycles and inconsistent producers.
- A resource may add logical ports classified as `read`, recording newly observed operand lanes. Existing ports, width, depth, reset/collision policy, evidence and every other resource field stay fixed. This describes extra observations, not additional physical RAM ports or circuitry.

These changes exist only in the new interpretation bundle. The original archived graph, native measurement and physical correspondence remain frozen. Successive extensions check the preceding trace/simulator identities, replace the completion shortcut and retain the preceding correspondence origin and extension review, so original scopes, coverage and refinement inventories stay reachable. The projection retains the refinement inventory and original physical provenance; resolving an unknown operand is evidence for that recorded execution, not a new measurement or an all-input equivalence claim.

## Complete computation circuits

A computation publication contains the exact recording, an index, and a separately hash-bound manifest of shared native tables. Use the prepared workflow above to avoid loading the entire source graph on every visit. Its rendering manifest binds the recording and source descriptor; all derivative parts and counts are checked before enabling the layer. Derivative parts are bounded to 32 MiB each and 256 MiB total. The complete-graph fallback verifies the source tables directly, with 32 MiB per-part and 512 MiB total bounds. Exceeding a bound fails explicitly; no successfully loaded prefix substitutes for a complete attachment.

**Computation circuits** draws the combinational fan-in of each qualified target bit written at a displayed clock. Traversal stops at sequential outputs, constants and external inputs. Data inputs, enables and resets remain distinct; all mux alternatives in that structural cone remain present. A finite correspondence witness for Q supports associating the register with the recording. It does not establish which native D/CE transitions occurred, or which combinational branches were sensitized. Unknown target bits and unsupported or disconnected frontiers remain counted as gaps.

The complete native pin/net graph, both supplied SDF corners and every event disposition remain retained in the source publication. Prepared clock layers refer to shared geometry and cone indexes derived from that graph. There is no worst-path ranking or hidden top-N population limit. All writes are included, including publication-driven updates without an explicit `register_compute` event. Read and semantic event families retain their applicability and evidence status; a semantic read is not invented as an electrical sampling event.

Use the existing **Actor**, **Task** and **Operation** filters to select recorded functionality. **Function** selects data, enable or reset circuitry. **Selected write or producer only** focuses on a selected write or the writes explicitly associated with its producer. **Minimum static cone delay** still selects entire cones by their conservative longest-path bound over the supplied SDF corners and conditions. It does not threshold the individual segment colors described below. The default **Register Q → D/control** timing scope includes only paths launched at native register outputs and ending at the selected D/enable/reset pins. Clock-to-Q and setup are excluded. External-input and constant-origin paths stay in the graph and drawing but are outside that metric; missing delays on them are not replaced with zero. A cone without a register-launched path has no applicable value. **Whole cone, including ports** instead requires complete timing throughout the cone, and remains unknown when external timing is absent. These bounds exclude clock-to-Q, setup, clock skew, constraints, timing exceptions and runtime sensitization. They are neither STA slack nor dynamic criticality. **Include cones without timing** defaults on, keeping missing timing distinct from zero. Filters never modify the retained tables or observer counts.

Choose **Color style** to compare different aspects of the same 3D geometry. The optional flat footprint retains its separate function colors:

- **Data / enable / reset** retains teal data, amber enables, purple resets and pale gray shared circuitry.
- **Sub-computation** assigns a stable hue to each destination register and its contributing circuitry across clocks. Storage and accesses use the corresponding resource hue. Circuitry contributing to several destinations is neutral gray; unknown identity stays distinct. The **Color key** names the visible destinations. The twelve-color palette can repeat, so hue is an identity hint, not a unique identifier or exclusive ownership claim.
- **Flow direction** runs from dark/cool source to bright/warm sink along each directed span. Storage runs from its earlier to later endpoint; recorded dependency links follow their source and target. Each span restarts the gradient, so color does not encode cumulative distance or elapsed time. Standalone circuit/access points and spans with unknown or conflicting source directions stay neutral. Native direction describes retained connectivity, not observed switching or dynamic sensitization.
- **Delay emphasis** dims lower bounds and brightens higher ones on a fixed capture-wide scale for the chosen timing scope, defaulting to **Register Q → D/control**. A routed span is colored by the maximum complete source-to-selected-sink path cost passing through its associated arc. That path cost is uniform along each span: this style does not draw a source-to-sink gradient. Different branches of one cone can have different colors; choose **Flow direction** for a gradient. This is a path bound, not the arc's incremental delay or the whole cone's bound copied onto every segment. Untimed storage remains neutral.
- **Computation + delay** keeps computation hue and varies its lightness using the same path-through-segment bound. Shared circuitry uses neutral lightness, while untimed applicable circuit contributions stay unknown. Untimed storage and access marks remain neutral in timing modes; categorical resource hues remain available in Sub-computation mode.
- **Computation + urgency** keeps destination hue and emphasizes paths close to the longest known path in the capture for the same timing scope. Its relative margin is `capture maximum path cost − this path cost`; the highlight bandwidth defaults to 1 ns. This near-longest structural emphasis is independent of the hypothetical arrival budget. It does not establish native STA criticality, dynamic switching or congestion.
- **Logic / net + urgency**, available in the arrival layout, distinguishes primitive logic arcs from net/transmission arcs by hue and uses the same capture-wide path urgency for brightness. Coincident geometry contributed by both kinds is marked mixed. Brightness describes the complete path through an arc, not that arc's local delay; the sink strip below shows local contributions.

For a qualified acyclic cone, preparation makes a forward pass from eligible sources and a backward pass from the selected sink. An arc's bound is its maximum upstream cost plus its own delay plus its maximum downstream cost. Registered scope starts at Q outputs and includes only arcs on a Q-to-selected-D/control path; port/constant-only branches remain drawn but are not applicable to that scope and stay neutral. Whole-cone scope also admits supported port and constant boundaries. Missing eligible upstream, arc or downstream timing stays unknown rather than becoming zero. Unsupported or cyclic regions cannot supply a qualified finite bound.

A rendered primitive shared by several arcs or destinations takes their maximum applicable path bound; any applicable unknown contributor keeps it unknown. Overview bins preserve the same distinction while combining destination identities and function roles. Timing scales do not renormalize when a window or semantic filter changes. Delay-bearing colors are unlit so face orientation does not change the displayed scalar; selection is highlighted separately.

The current arrival, path-color and sink-inspection data require rendering algorithm 4, which retains exact native pin names, per-pin arrivals and path-through-segment costs. Re-run `prepare-render.mjs` into a fresh directory from the retained complete computation publication (or an older rendering publication that still contains its full source tables). Algorithm-1/2/3 derivatives must be rebuilt, not relabelled: earlier formats lack pin-arrival heights or exact native pin labels. This is offline re-preparation from the saved graph and SDF-derived arcs, with no new capture or native run; see [the preparation workflow](computation-routing.md#prepare-rendering-indexes). Unprepared publications retain function/direction colors and static-delay filtering; a capture with no finite applicable path bound has an unknown scale.

Native logic positions and wire-tile memberships appear as cubes; **Connectivity + switches** adds the retained PIP positions. **Routing connectivity** in the flat layout connects those positions with dashed schematic chords following used-PIP order and endpoint attachments; the arrival layout uses the continuous propagation and explicit endpoint-bridge styles described above. Exported wire memberships within a routing node are unordered: they do not supply a metal polyline, sub-tile track coordinates or exact bends. A diagonal chord therefore denotes connectivity between its endpoints, not a diagonal physical wire. The viewer does not invent Manhattan bends to make it look routed. Unknown attachment branches remain explicit; hiding unmapped geometry suppresses their fallback lines while retaining mapped positions. Native timing paths remain a separate optional static STA comparison.

At drawing time, coincident tile-space marks and spans are combined, including overlapping portions of axis-aligned collinear spans. This avoids repeatedly painting the same display geometry. The combination retains contributing roles/destinations, maximum applicable path costs and unknown timing; incompatible directions become neutral. Separate native records, nets, arcs and evidence identities remain intact. Sharing a displayed coordinate or chord does not mean two nets are electrically connected. This is a display aggregation at the available coordinate resolution, not a more precise reconstruction of the layout.

## Inspect paths to a sink

In the arrival layout, **Paths to sinks · logic / net delay** lists the native target pins of the currently visible data, enable and reset cones. Each role/pin row combines its recorded write associations across the displayed clocks. **Find sink** searches exact pin names, register resources and roles; it changes the list, not scene membership. Paging retains the complete matching population. A shortened table label exposes the full native name on hover and when selected. Window, semantic and cone filters determine the population; removing the selected sink clears its path and arc highlight.

**Longest ns** is that sink's qualified longest source-to-sink SDF envelope in the chosen timing scope. **Gap ns** is the slowest known visible sink's bound minus this sink's bound. It measures relative severity within the current population, not STA slack, budget margin or the benefit achievable by optimizing that sink. Unknown contributors prevent a complete numeric bound; outside-scope sinks remain separate. The gap's visible-population reference differs from the fixed capture-wide reference used by urgency colors.

**Path view** chooses how much circuitry to draw:

- **All circuitry** keeps the complete visible structural cones.
- **Longest path to every sink** draws one deterministic representative maximizing chain per qualified sink contribution, sharing coincident geometry and retaining unknown sink markers. It does not enumerate all tied paths.
- **Selected sink: longest path** focuses on the selected role/pin. The strip and summary explain its representative chain, including whether alternative maximizing predecessors were encountered.
- **Selected sink: near-longest paths** draws the union of arcs lying on an eligible path within **Near-longest margin** of that sink's longest bound. Zero margin includes all maximizing alternatives. This corridor can contain reconvergent branches; arbitrary recombinations of its arcs need not themselves be near-longest paths. Unknown alternatives remain explicitly unresolved, not classified as short paths. If any contribution to the selected sink is unknown, this mode retains its eligible closure without applying a margin to an incomplete bound.

Focused sink modes hide other storage, event, dependency and static-report overlays; switching back to All circuitry or Longest path to every sink restores those display settings. On a wide screen the sink inspector sits beside the scene; collapse it to recover the full canvas width.

Selecting a sink opens an ordered source-to-sink strip. Its logic and net/transmission segment widths show each arc's local SDF cost, and their sums reconcile with the representative chain's bound. Parallel paths are never added together. Click a strip segment or an entry under **All ordered arcs** to highlight its available 3D geometry and read exact source/target native pin names, local delay and cumulative chain cost. Zero-delay arcs remain in the ordered list; an entirely zero-delay chain uses equal strip widths. Unknown or inapplicable sinks supply no claimed maximum chain. A known-timing arc with located native endpoints can remain connected by an explicit schematic bridge even when its native route is unresolved; missing timing or coordinates remain unresolved.

Selecting a chain or corridor changes membership and path-color annotations before geometry aggregation; it does not recalculate pin heights as though other inputs disappeared. The arrival view still shows each pin's latest structural arrival. Tied maxima use deterministic native identities, not an assertion of a unique cause. These are independent per-arc SDF envelopes: a chain need not be jointly sensitizable or match one timing corner. See [timing interpretation](timing-report.md#what-the-numbers-establish) for the excluded clock/endpoint checks and the distinction from an execution period.

## Attach saved route detail

Attach a completed route export to the exact projection used to select its static timing paths:

```sh
node scripts/attach-routes.mjs \
  --view ORIGINAL_VIEW.json \
  --selection /path/to/routes-1/selection.json \
  --routes /path/to/routes-1/routes.json \
  --out NEW_VIEW.json
```

The command checks the selected view's exact SHA-256, unchanged path records, retained timing-report provenance, checkpoint/build identity and the export's selection hash. It validates the route topology and preserves the original native build through explicit correspondence provenance; it does not reinterpret the execution graph or capture. The new projection records all three input byte lengths and digests. These inventories are trusted local annotations, not signatures or fresh validation of a native measurement.

The output must not already exist. Open the new projection with **Open file**; the command leaves the original projection and example index unchanged. Limits are 128 MiB for the view/output, 4 MiB for selection and 32 MiB for route detail. Route topology uses device tile coordinates, with unresolved attachments and unavailable segments explicit; it is not sub-tile metal geometry, measured switching or a new causal edge. No simulator, native tool, original preparation command or old report reader runs.

## Read the picture

- The **clock stack** shows distributed storage accesses at their associated native tile positions. Multiple cells at one tile can share a solid cube. Writes select the logical write-mask bits whose cell identities are known; producer-qualified read masks select operational bits. A read without that mask shows whole-word context instead. A solid cube does not imply a known consumed subset or electrical switching: inspect the access mask and binding details. Turning off **Distributed accesses** groups positions, whose centres are not computation locations. Unresolved bits and operations can appear on the labelled unknown rail; a delayed response does not borrow its source register's location. The memory fixture uses logical resource/address lanes throughout.
- **Actor, activation, operation and task** filters use recorded fields. Operation is the available phase/action vocabulary, not a newly inferred computation stage. Activation choices come from the current actor/window. Clears and window navigation never discard the underlying graph.
- **Show unmapped participants** controls geometry only. Uncheck it to suppress unknown-location operation/access glyphs, unknown portions of storage histories, and dependency lines with an unlocated endpoint. Placed portions of partially mapped words stay visible. The event list, inspector, traversal and metric totals are unchanged; a hidden participant is still unknown, not absent. The control is disabled for captures without a native catalogue, whose logical lanes remain useful. Clock labels are deduplicated and kept apart on screen; axis labels take priority over optional off-window dependency labels. Exact clocks and aggregate-dependency counts remain available in the list and inspector.
- **Inputs** and **Consumers** traverse only recorded value, read-request and required-control dependencies. A public annotation can name several independently bound graph endpoints; selecting it follows all of them, visiting shared contributors once. Unbound annotations stay context. Root versions stop traversal, the traversal cap is explicit, and the inspector identifies the result as partial recorded ancestry. Same-clock chronology, placement, equal payloads and wire connectivity create no extra causal edges. Resource-order relations remain distinct and are not included in the default causal traversal. Semantic filters clear an operation or anchored annotation when none of its endpoints match anywhere in the recording; moving the clock window preserves off-window ancestry.
- **Storage links** default to versions with recorded uses, even with no selection. Residence ends at the last recorded use, including reads on the replacement clock and explicit old-value inputs to masked writes. Holds and delayed responses do not extend the source word’s use. Off-window consumers still preserve the preceding storage. Enable **Full storage history** to restore all matching words and their entire residence; the inspector always retains that history. No recorded use is not proof of dead state: the recording may omit consumers. Thicker opaque links join a write at C to its new Q at C+1; a cube marks that next sample. Thinner opaque links retain the same version between samples. An equal-valued write is still a new version. Replacement, reset and capture boundaries stop the span; a final write without a following Q sample gets no invented cross-cycle link. Residence is not an attributed wait. Incomplete captures remain visibly uncertain.
- The optional **flat chip** in **Chip & resources** draws installed primitives once and highlights the selected resource’s associated native cells. A wide encoded register can occupy many scattered FFs; this resource highlight is storage placement. The separate computation-circuit layer adds recorded-write fan-in and routing when its complete attachment is available. The unknown rail beside the stack is a layout convention, not external circuitry. Expand cell details or select a highlighted cell for native identity, kind, site, BEL and tile coordinates. The storage resource shows supported and unknown bits separately. Partial word correspondence does not establish the complete circuit footprint of an actor operation.
- **Native timing path** adds ordered combinational pins and their selected routed branches from the saved setup report. Pink marks logic cells, violet marks the actual tile-local wires belonging to each selected routing node, and gold marks programmable interconnect points (PIPs). A node can span several tiles: all exported wire memberships remain visible, without averaging them into a centroid or sorting them into a fictitious trajectory. Connections join successive PIPs electrically; tan spans cover unavailable site geometry. The main 3D scene uses dashed opaque chords; the flat comparison uses dotted lines. Both distinguish the connection from a measured metal trajectory. These are tile-resolution routing footprints and topology, not exact metal-track bends inside tiles. The overlay appears on a comparison clock layer and on the flat chip, independently of the selected execution trace. Its per-arc details show branch disposition and missing geometry. Only a uniquely identified source-to-selected-sink branch is drawn; other fanout is excluded. The recording does not establish that this static path was sensitized on the displayed clock.
- The **timeline** retains the whole recording while the stack shows a movable window. Public completion boundaries and reset incarnations are separate markers. “Selected step” opens the recorded step interval; “Completion record” selects its public annotation and any explicitly bound contributing endpoints. The annotation itself creates no graph event or edge.
- **Window metrics** count elapsed clocks as the exact half-open window length. Load and hold word-clocks sum the visible adjacent-clock links of logical storage words, following the semantic filters and recorded-use/full-history setting. Concurrent words add; these counts are neither elapsed time nor a critical-path duration. A one-clock view has no storage link to count. Installed native cells come from the unique catalogue once, independently of filters and repeated layers; absent placement remains unknown. Wait counts require explicit `metric_hints.wait_operations` in the projection or bundle, naming producer-qualified per-clock observations. The display separates wait-event samples from distinct observed clocks, never treating arbitrary gaps or storage residence as waits. All counts retain the capture’s declared observer scope and incomplete status.

The operation list provides keyboard-selectable alternatives to overlapping canvas dots. The inspector identifies producer/consumer versions, activation, storage history and source evidence. Context dots are reused from one physical table; appearances across time do not multiply installed area. Colors follow the selected function, destination, direction or path-delay style; the inspector retains exact identities regardless of palette collisions. Neither establishes exclusive physical ownership or gate switching. Dependency connections are schematic. Native routing overlays supply measured wire-tile memberships and PIP locations; their connecting spans remain schematic. Distributed access locations do not supply missing combinational ancestry or bit-to-bit dependency pairing. Aggregate word dependencies remain labelled when that pairing is unknown.

Select a storage link or use **Resource → Storage versions in view** to inspect its version, producer and consumers. Selecting a resource emphasizes all its visible versions. **Expand selected word into cells** is enabled by default and draws the selected word’s qualified cells at their device tile positions; shared/folded cell identities draw once per word version. Partial, candidate and unplaced portions remain on the unknown rail. Cell expansion associates simulated storage with qualified native value locations; it does not establish native write-enable activity, electrical switching or exclusive task ownership.

Unselected storage words remain grouped to keep the background legible. The selected word expands into cells by default; turn off **Expand selected word into cells** to group it too. Actor/activation/operation/task filters select storage through explicit associated events, including consumers outside the clock window, without assigning those actors to every stored bit. Background storage stays neutral. Every matching access, storage span and selected dependency contributes to the drawing; coincident geometry can share a displayed mark or span. The canvas does not stop at an item count. Wider windows and expanded physical footprints can take longer to draw. Use Window, semantic filters and the footprint/expansion controls to choose the amount of detail. Counts beneath the stack report the actual drawing size. Dependency traversal still has its separately disclosed 1,000-operation bound, and the operation list shows its first 250 rows; neither limits the unselected canvas events. The complete event/version graph stays available; the prepared mode keeps rendering indexes in memory while retaining the full native source graph on disk. Clipping marks preserve off-window boundaries, and a one-clock view has no pair of samples to connect.

## What the first example supports

The N2 step occupies `(1774, 1873]`, displayed as C1775–C1873: 99 clocks. The current expanded live graph contains 61,764 events, 151,134 versions and 84 resources. Five added input taps preserve all 587 preceding taps and eleven public fields at every one of the 2,369 clocks; both the live and reset recordings replay exactly. The graph retains every original event time/access and stored-word identity. Reviewed refinements resolve unknown transient roots and add observation read lanes; the prior archived graphs remain unchanged.

**Completion C1873: accepted-transfer ancestry** selects both coordinate status frames. Their ancestry now reaches accepted source publications, capture-slot arrivals, payload writes and selected scalar register computations. Across the full live recording, 357 publications account for 708 arrivals/payload writes and all 28 boundary transfers; one publication remains pending at the finite end. The numerical adapter adds 19,228 selected-operand reads, resolves 6,929 write-input roots and checks 3,974 of 7,637 enabled D values exactly. The remaining 3,663 values are unknown, not mismatches.

The selected completion has 21,949 reachable recorded operations, including 2,281 scalar computations, of which 2,130 have checked values. The interactive traversal retains its explicit 1,000-operation cap. Unknown roots remain extensive: omitted small control-register histories, an unbound transformed XLS state bit, external inputs and publication-layout controls prevent complete causal attribution. Computation events have no inferred native logic location. This is selected operational ancestry, not electrical sensitization or a complete critical path.

Start with **Register residence: C1852 → C1866** to inspect `v/25067` in the 537-bit encoded word. Its stored value occupies C1853–C1866, and a read feeds actor/3 acceptance. ## Metric definitions

Installed-cell concentration uses fixed 16 × 16 native tile bins aligned to coordinate zero. Each catalogue identity contributes once, regardless of the number of clock layers or operation filters. The blue shading scales within this view; it is a distribution of installed primitives, not a device-capacity or routing-utilization percentage. Missing tile units suppress the distribution, and unplaced/unknown-kind counts remain explicit. Separate primitive-kind counts are retained in the metric data.

Temporal activity counts the recorded operations in the selected half-open clock window and semantic filters, with separate totals for clocks containing observations and the peak number of simultaneous observations. Missing observations are not idle-time evidence; logical operation counts do not measure gate switching. Wait samples remain separately classified by the producer, rather than inferred from gaps.

Elapsed clocks are `endCycle - firstCycle`. Storage word-clocks intentionally add concurrent words and therefore are not elapsed clocks. The optional hypothetical period multiplies elapsed clocks exactly once, using bounded floating-point nanoseconds; it does not add STA data delays, wait counts or storage word-clocks. No qualified physical period is supplied by this example. A failed target and a constraint-equivalent period remain distinct from an execution measurement.

Focused fixtures change placement, add stalls, overlap words/operations, narrow filters and omit metadata. They check that installed concentration is independent of temporal changes, that temporal distributions respond to the changed recording, and that hypothetical elapsed time scales only with interval length. None predicts a speedup or recovers a complete critical path from partial ancestry.

## Check storage against the recording

```sh
node scripts/check-storage-view.mjs web/data/live-1.json
node scripts/check-storage-view.mjs web/data/memory.json
```

This independently advances each recorded word through every clock, then compares that replay with the viewer's compressed load/hold intervals. It checks pre-edge reads, full and masked writes, delayed responses, reset roots and final writes. The JSON report binds the exact input SHA-256 and reports qualified logical edge counts only for complete declared write coverage. Missing coverage remains unqualified; contradictory transfers reject. This is a check of the saved access history and its visualization, not another simulation, a native write-enable proof or a recovery of missing numerical ancestry.

Inputs are bounded to 128 MiB and one million adjacent-clock/word comparisons. `--max-comparisons COUNT` may lower the comparison budget; repeated limits use the last value. Exceeding the limit rejects rather than silently sampling. Normal unit tests use small synthetic histories; these optional saved-case checks require only the prepared files.
