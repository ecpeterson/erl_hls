# Hardware-domain endpoints

`hls_domain_fabric` implements the runtime library's `hls_domain_backend` contract over independent, deployment-owned management and application brokers. It consumes an emitted interface and retained record codecs; it does not compile sources or infer application recovery policy. `hls_domain_endpoint` gives each ready actor incarnation an ordinary monitored ERTS endpoint, usable directly or through the [distribution node](../node/README.md).

The generated bridge supplies incarnation admission, response sequencing and the accepted-output frontier. The backend waits for that frontier before orderly actor retirement. Broker loss, invalid framing and an incomplete frontier terminate local endpoints with connection uncertainty. Neither a backend restart nor an owner monitor certifies physical reset or releases external resources. Deployment code remains responsible for exclusive transport attachment and actual descriptor retirement. The generated sideband session reset preserves actors; `hls_domain:reattach/3` binds new host proxies to the same observed incarnation without replaying uncertain work. See the [session boundary](../../../docs/domain-recovery.md#framed-hardware-backend).

[Wire codecs](../../wire/README.md) contain `hls_domain_wire`, which uses the same retained actor schemas for calls, replies and effects. Typed application messages and current-call ownership remain separate from the lifecycle controller's one retained management transition.

`hls_supervisor_fabric` is the parent-management adapter for a compiled supervisor. It presents the ordinary domain-backend interface to a host OTP parent, transports a previously reserved identity grant and carries no child application traffic. Each independently supervised child keeps its own `hls_domain_fabric` lanes and endpoints.

For a locally supervised child, `hls_domain_fabric` watches an exact ready incarnation before publishing endpoints. One hardware retirement record preserves that lifetime's terminal cause and accepted-output frontier across autonomous replacements. Host acknowledgement follows output delivery and endpoint death; only then may another incarnation be watched. Skipped lifetimes require no retained work history. Missing evidence remains connection uncertainty. On reconnect, an unchanged incarnation uses `hls_node:reattach_domain/2`; an explicitly selected newer incarnation uses `hls_node:publish_domain/2` and fresh PIDs. See [framed parent and child publication](../../../docs/domain-recovery.md#framed-parent-and-child-publication) for the control path and deployment obligations.

`hls_domain_channel` is the pure mailbox-crossing ownership kernel shared by native execution and generated hardware. Callers retain its state and supply exact endpoint lifecycle observations; it starts no process and owns no transport I/O or payload register. Its checked records live in [include/](../../../include/README.md). The downstream `hls_domain_channel_build` compiles the same service adapter and adds retained payload storage outside both endpoint reset regions. This dependency points from lowering into runtime: the kernel imports no compiler or lowering modules. See [crossing mailboxes](../../../docs/domain-recovery.md#mailboxes-between-reset-domains) for binding, credit, reset and deployment assumptions.

`hls_domain_channel_fabric` carries bounded channel-management requests over one deployment-owned broker. Per-channel capabilities protect binding and fencing; application data and credits stay on hardware lanes. A lost mutation response leaves an unknown outcome that subsequent inspection must reconcile. Owner loss leaves a fence obligation in the surviving adapter, while broker loss means connection uncertainty rather than successful retirement.

`hls_domain_channel_instance` is the ordinary OTP worker placed after its two supervised domain representatives in a dependent restart group. It waits for ready endpoint incarnations, binds that exact pair and observes the binding. It does not replace actors or relay messages: the surrounding OTP supervisor owns restart policy. Child startup is distinct from confirmed channel readiness. Both the domain owners and channel adapter must outlive this subtree. See [framed crossing management](../../../docs/domain-recovery.md#framed-crossing-management) for the generated interfaces, supervision example and explicit transport reattachment boundary.
