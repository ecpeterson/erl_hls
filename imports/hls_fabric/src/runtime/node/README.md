# Virtual distribution nodes

`hls_node` is the public manager for a virtual device node. `hls_node_sup` owns its manager, acceptor and connection supervision; `hls_node_acceptor` accepts TCP distribution peers and `hls_node_connections` supervises their handlers. `hls_node_connection` adapts supported ERTS signals to the existing fabric brokers, using `hls_node_wire` for distribution packet details. `hls_local_dist` supplies the optional in-process distribution carrier for locally hosted nodes.

The [application supervisor](../../app/README.md) starts configured node trees. [hls_lowering planning](../../../apps/hls_lowering/src/planning/README.md)'s `hls_node_topology` provides normalized scheduled-actor bindings, and [wire](../../wire/README.md)'s `hls_node_binding` validates and packs those retained deployments using `hls_host_codec` catalogs. `hls_node_domain` binds ready `hls_domain` incarnation endpoints and checks replacement publication; node connections forward bounded requests and actual endpoint monitor exits. `hls_node_requests` owns queued admission and eventual reply destinations for both managed endpoints and legacy wire channels. Managed endpoints acknowledge admission separately from completing a call, so retained calls use per-actor completion slots without stopping unrelated actors or release casts. A cast rejected as busy before admission waits for explicit capacity notification; accepted or uncertain work is never replayed. An unrecoverable ordinary-cast rejection withdraws only that peer's target binding with `noconnection`, without claiming source death or changing domain state. A finite shared distribution input can still pause behind a flood of not-yet-admitted messages. Node startup does not compile sources, activate managed domains or create physical transport brokers.

This is a limited distribution endpoint, not a second ERTS or an implementation of arbitrary remote Erlang behavior. The supported signals, incarnation and reconnection rules are in [device sessions](../../../docs/device-sessions.md) and [actor addressing](../../../docs/actor-pids.md). Add carrier behavior here, packet schemas in `wire/`, and hardware generation in `hls_lowering`'s backend.
