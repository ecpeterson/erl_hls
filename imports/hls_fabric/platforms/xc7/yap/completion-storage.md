# Completion storage and reduction-port constraints

Preregistered against private #41 at `0079c44`. First change completion payload storage only. Each scheduler has one executor-result producer and one retirement consumer, so this has no multi-writer banking problem. Preserve logical depth, the retained completion boundary, empty bypass, registered push readiness, full recovery, ordering and reset-visible behavior. Do not reduce the number of outstanding actor reservations.

The four-actor replay has four depth-three result FIFOs, with 384/987-bit source/phi results. The current general XLS ring allocates four physical rows; together those FIFOs map to 10,028 FFs. Phi results contain 540 machine bits, 392 effect bits and 55 identity/control bits. Keeping the whole result postpones state commit until publication/metadata retirement; replacing it with a pointer requires a separate ownership design, not field deletion.

Experiment: retain the generated ring control and replace resettable, individually enabled payload rows with one unreset addressed write port. Reset clears validity/pointers, so unread invalid payload is unspecified. Request XC7 distributed RAM, whose asynchronous read can preserve the current FIFO interface without BRAM prefetch latency. Hypothesis: remove most of the 10,028 completion FFs in the four-actor replay, retain one-result-per-cycle capability and every visible interface cycle. LUT cost is uncertain: expect roughly one memory LUT per surviving payload bit plus selection/control, not a guaranteed LUT reduction. No clock or whole-step improvement is predicted. Keep the small depth-one specialization unchanged.

Gate implementation on symbolic reset/stall/full/wrap comparison of each distinct FIFO shape, an isolated mapped-memory census, and cycle-exact complete-replay comparison. Only then synthesize the complete replay. Count distributed RAM as LUT area. Do not infer a full-D6 resource saving from this fixture; apply the same storage-only substitution to a complete tile separately if the screen succeeds.

Reduction storage needs a separate port ledger. The replay's source-fragment plane has four indexed directional banks. The distributed tile instead has independently backpressured input lanes and per-actor collectors. Multiple sources may produce same-direction contributions simultaneously; one RAM per direction does not preserve that interface. Actor-state-backed folding previously serialized intermediate contributions and required repeated state visits. Do not restore it. A RAM proposal must identify every concurrently accepted read/write, establish a conflict-free banking assignment or explicit independent front buffers, preserve separate credit/capacity ownership and measure last-fragment-to-aggregate latency. A lower-bandwidth bank with unmeasured buffering is not a throughput-preserving replacement.

Historical check: public `8769cae` introduced a separate reduction RAM and `ade50c0` returned its receptacles to registers. The latter's recorded three-shard probe recovered 315.875→271.042 clocks/step by removing the extra RAM round trip. `c447fed` then transposed destination accumulators into source fragments: one source-batch admission and one destination retirement mean each directional bank needs only one enqueue and one dequeue per activation. Its notes explicitly require nonmoving payload slots plus narrow head/valid metadata before a literal 1R1W lowering, since shifting lookahead would otherwise create a second payload write.

For that replay layout, a candidate bank stores payload at `(source, slot_bit)`, keeps head/count in registers, writes one selected tail, and reads the selected head. Pop changes metadata instead of copying payload. Four banks preserve four parallel contributions. Asynchronous distributed RAM can preserve the existing read latency; BRAM needs a separately measured read/prefetch design, including same-address old-data behavior. This argument does not cover the distributed topology's independently active collectors. Its next design step is to enumerate producer conflicts and simultaneous collector reads, including bursts from held per-actor outboxes. Banking by compass direction alone is insufficient. Preserve independent front reservations if any storage port is shared, and establish a finite buffering/service bound before accepting an average-bandwidth argument.

The completion experiment leaves every reduction lane and collector unchanged. It neither commits actor state early nor reduces completion capacity. Both would change ownership/progress and require independent experiments.
