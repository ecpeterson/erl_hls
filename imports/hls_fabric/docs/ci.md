# CI coverage

CI selects tests from the complete diff against the PR target branch, or the preceding commit on a `main` push. Markdown and rendered documentation alone skip integration jobs. Source contracts and Dialyzer still run. Executable examples, fixtures and unknown paths require tests; unavailable history requires every group.

Scheduler changes run software checks, focused RTL regressions, the execution backend and complete D3 shared-scheduler memory with source-fragment reductions. Small noisy board tests cover both ordinary and offloaded reductions. Packed-link sweeps, direct-actor bridge experiments and board bring-up run when their inputs change; dependency and workflow changes select every group. `tools/ci_groups.json` records these boundaries. Rules select the first matching group set; unrecognized files fail closed.

Successful workflows retain a qualification record keyed by all tracked non-documentation content, including dependencies, test harnesses and workflows. An exact match skips repeated integration jobs on report-only follow-ups. Failed or cancelled jobs cannot qualify inputs; missing records cause testing again. GitHub's branch cache isolation applies, so PR records cannot qualify `main` builds. This saves repeated testing without relying on commit flags or a truncated changed-files API.

The Execution backend workflow runs source-derived actor/network checks in a separate `source-backend` job, alongside scheduler/debug checks and repetition application checks. All three must succeed (or be legitimately unselected) before their shared input qualification is cached. This separates the accumulated source-network workload from the scheduler job’s 25-minute limit without dropping checks.

Manual dispatch always runs tests. The CI workflow's **extended** option adds direct/ordinary and shared/ordinary D3 references plus the full packed-link performance grid. The Execution backend workflow also runs complete D3 debug qualification when dispatched manually. Use these for changes to those paths or for broader release qualification; no periodic sweep runs automatically.

Automatic tests retain active reset/restart, BEAM comparison, independent clocks, blocked peers, framing, credit isolation, reduction collection, publication ordering and debug-query witnesses. The eighteen-tile D6 simulation and physical timing campaigns remain local measurements. These witnesses do not establish general equivalence.

OTP remains pinned through `setup-beam`; the shared `.github/actions/beam-tools` action downloads rebar3 3.24.0 directly and verifies its SHA-256 before execution. It does not depend on GitHub’s release-list discovery.

RTL tools use Ubuntu’s signed Noble package archives directly, without optional recommended packages. The shared `.github/actions/rtl-tools` action bounds index refresh to one minute and package downloads to two minutes, then installs from the downloaded files. A slow package server fails during setup instead of consuming the test budget; runner APT configuration is unchanged.

Phi bridge simulations retain the original instrumented netlist and compile a separate `simulation.v` after Yosys combinational cleanup (`opt_expr` and `opt_merge`, both with `-keepdc`). Register enable and reset logic is not rewritten. A small four-state differential witness checks pre-clock values, reset, hold and X/Z inputs; the complete D3 run retains its clocks, rounds, reset and BEAM comparison. Host phase timings distinguish wall-clock setup, diagnosis and experiment time from simulated device throughput.

Successful jobs upload no artifacts by default. Failures retain bounded diagnostics for two days; manual dispatch can request them with **diagnostics**. Each bundle contains at most 4 MiB of file data: up to 256 files, 256 KiB each. Large logs retain their tails; oversized structured files and generated Yosys netlists are omitted, with omissions listed in the bundle index. Job summaries report compressed upload sizes. Compiler caches and successful-input qualification records are unaffected. Retain important measurements in the external artifact archive; see [artifact storage](artifacts.md). Timeouts allow runner variation and are separate from workload performance.
