## Principles that can be generic

| Portable architectural rule | Target-dependent choice |
| --- | --- |
| Give mutable metadata one local owner; colocate its frequent readers, writers and payload storage. | Island dimensions, actor count, memory columns and resource headroom. |
| Bound selection fan-in and the physical reach of enables/validity. Move compact commands between owners. | Local decode/driver replication and the profitable control encoding. |
| Register genuine inter-island transactions; account for feedback latency and finite credits. | Crossing pipeline depth, register locations and clock-region/SLR constraints where applicable. |
| Partition by access and communication demand, not actor count alone. | Placement-distance and routing-capacity costs calibrated to the device. |
| Preserve stable semantic identities and source→resource mappings. | Module preservation, selective placement constraints and implementation directives. |
| Separate immutable bulk values from short-lived control and hot mutable fields. | LUTRAM/BRAM/URAM mapping, aspect ratios, read latency and available ports. |

The partitioning graph should include **resource owners**, not just actors: RAM ports, collector state, executors, publication queues and debug readers. Weight crossings by surviving bit width, rate, fanout and recurrence sensitivity; also charge local mux/decoder cost and maximum offered work. A narrow, pipelined boundary can be cheap despite crossing a region; an ostensibly local six-row selection can be expensive. Minimize neither cut count nor wire length in isolation.

These principles carry across FPGA families; the best tile size and constraints do not. Keep a portable semantic/access plan and a small target description of resources, region capacities and crossing costs. Do not put slice coordinates into Erlang source. Do not require a perfect placement predictor before starting: a few representative connected components and the existing routed control can calibrate useful approximations.

AMD recommends selective floorplanning with few crossings, rather than indiscriminately constraining the whole design. Tight Pblocks can remove useful placement freedom or crowd boundaries. Start with free placement versus loose grouping of a complete owner domain; keep both results. Do not blanket `DONT_TOUCH`, and do not infer a multi-die problem from wire delay alone. AutoBridge/TAPA is a relevant precedent for coupling coarse floorplanning with communication pipelining. Its useful lesson is the coupling, not its reported speedup: our feedback-heavy actor protocol has much less freedom to absorb added latency than independent streaming tasks. Retiming a crossing must preserve throughput under the actual recurrence and credit budget. ## A. Local execution tiles with resident protocol state

**Change:** split cheap per-actor ownership from expensive shared computation. Keep each tile's hot phase, readiness, bank ownership and mailbox metadata near its memories. Share callback datapaths over narrow operand/result interfaces rather than repeatedly sending the whole mutable machine through a large select/update/retirement circuit. Cold actor state can remain in BRAM; hot fields need not share its transaction boundary. Keep the next request and the computation consuming it physically adjacent.

This is neither fully dedicated actors nor more copies of today's scheduler. The previous per-actor/grouped-ownership attempt replicated retirement/opening decisions and grew representative LUTs by 9.7–17.7%. The proposed distinction is to distribute **ownership** while sharing **classification/computation**, with compact committed commands. It fails if implementation recreates a many-to-many request mux or whole-context acknowledgment. Start with the existing six groups as physical domains; consider smaller domains only after pricing this split.

Use an ownership/access ledger to choose the cut: who reads each field, who may change it in the same clock, which facts are already established, and which results must be visible before another actor activation. A request for a snapshot completion should not carry unrelated ordinary-message fields. Narrow exceptions and diagnostics still travel with their owner; this is not failure-check removal. Include fault presence, validity, credits, commit and debug coherence in the timing boundary. A local readiness predicate that still waits for a selected shared diagnostic result has not removed the retirement dependency. Share detailed diagnostic generation only where it does not restore the hot control path.

**First discriminating comparison:** the census and failed same-RTL grouping are complete; do not repeat them. Close a staged command/commit/eligibility protocol on accepted hardware, including reverse readiness and per-bank hazards. The [accepted-path review](/Users/ecpeterson/Documents/code/hls_artifacts/runs/campaign-feasibility-2026-10-07/report.md#concrete-routing-cuts-after-reinvestigation) identifies pending-header→readiness, output-predicate→stage-enable, transparent operand-return and publication/credit competitors. Use an executable cycle/ownership model before one connected six-actor comparison at actual 19/22-producer dimensions. Carry projected fields, sustain independent progress, and include coordinator/barrier and cold-path coverage before full-core qualification. A controller-only module with unconstrained ports is not representative enough.

**Useful result:** several near-critical families shorten together, or a substantial part of request/result traffic disappears without extra activation work. Map effects on the complete core before assigning a frequency forecast. Replicated control, added round trips and poorer memory packing are charged to the whole-core budget; reject them when the measured routed gain does not justify their cost or fit is lost, even if an isolated cone is faster. More local registers may be worthwhile; “more BRAM” is not the objective.

## B. Compile regular protocol phases as bounded dataflow regions

**Change:** recognize a closed phase protocol and lower its communication/ownership once, instead of executing every normal command, entry, collection and acknowledgment through generic actor dispatch. Keep the Erlang callbacks as the computation and semantic reference. A region can have local phase tokens, fixed member ports, bounded version storage and pooled phase-specific engines. Retain a generic actor boundary for irregular traffic, configuration and failures.

The checked dispatch selectors correct the profile labels: all 2,484 `snapshotting / entry` events are completed-gather computations; snapshot opening/publication is already folded into prior transitions. The 1,728 `ready / entry` events perform local successors. The [reconciled ledger](/Users/ecpeterson/Documents/code/hls_artifacts/runs/regular-phase-budget-2026-10-06/report.md) retains these computations and selects the complete merge region, from launch through transfer completion and done admission. A resident-state-only split keeps every generic visit. The selected region replaces launch/completion visits with owner commands while retaining one shared merge computation; busiest-owner snapshot writes still demand 81.05 port slots per mean sheet.

This differs from the failed continuation fold: that combined more callback work but retained the same shared control/retirement machinery. A dataflow region must change that machinery's **protocol**, not just fuse function bodies. Keep computation staged where useful rather than building a larger combinational callback. Separate phase engines are an option when distinct field/port needs remove a large shared dispatcher; merely duplicating admission logic and adding queues is not useful specialization. Global busy decisions after merge remain real dependencies; eliminating their messages does not eliminate the decision. Require the generated region to remove a complete generic selection/retirement/acknowledgment dependency, and inspect the mapped result before routing. If a register stage is needed, preregister its recurrence and cycle cost against routed period; exact-cycle preservation in r7 is not a universal campaign restriction.

Start with one complete merge region, including snapshot opening, proposal output admission, transfer reduction and logical commit. Generate the phase/access summary from source and topology; initially reject unsupported guards or accept explicit, checked placement assertions. Preserve fixed neighbor priority, current/successor keys, inactive versus absent members, early-arrival storage, exceptions and per-owner correction order. A dynamic fallback that retains all the old selection hardware may provide no physical benefit; measure it explicitly.

**First discriminating comparison:** write a transaction schedule and cycle/port ledger for that one region, with source state transitions still observable. Fit its service demand into a complete-sheet ledger covering all mandatory phases, repeated merges, transfer completion and commit. The target table budgets a whole sheet, not just this region. Account for admission/publication rather than predicting from removed visit counts. Only then lower a normally expressed Erlang fixture. Compare the complete decoder and a second regular-phase application before treating it as a general backend mode.

**Risk:** protocol inference is substantial compiler work; a wrongly inferred phase or version bound changes behavior. The existing region measured 10.96% fewer cycles but failed its native area screen and retained a long pending-command→retirement/eligibility chain. That cycle saving does not give B priority over a simpler routing cut on the accepted hardware. Use B when checked protocol specialization demonstrably enables the physical boundary or removes its excessive control/area cost. Its routed benefit and revised area remain unmeasured. The useful reusable product is a checked regular-region lowering, not a Snowflake-specific bypass.

## C. Publish versioned neighbor state once, then read it locally

**Change:** replace copies of the same immutable snapshot into each recipient's gather store with one published version plus neighbor references. Within a tile, recipients access that version through a planned bank/port schedule; across tiles, send only boundary halos. Keep merge proposals and mutable edge updates separately owned. A compiler may realize the original finite message protocol this way only after establishing that consumers see the same immutable values and ordering.

This targets transaction count and physical bit movement simultaneously. It is not scalar reduction: consumers retain source-defined member order. Existing width-two publication already shares equal payload selection, so saving another copy of that mux is not the opportunity. The opportunity is removing recipient copies/writes and local message transport, then replacing gather-store reads with planned donor-version reads. Every consumer still needs its values; logical acceptance, epoch, membership, duplicate and failure checks remain unless separately established. Across 128 sheets there are 19,656 vertex snapshot publications and 55,692 recipient member writes: a 64.7% payload-write reduction is the optimistic write-once count, not a cycle saving. Cross-tile copies, extra replicas and version metadata reduce that opportunity.

**First discriminating comparison:** derive the actual read set and version lifetime for every consuming callback. Compare distributed copies, small replicated banks and a colored bank schedule. Charge all neighbor reads, simultaneous writers and boundary traffic. A single BRAM holding every snapshot can replace parallel writes with a worse shared-read bottleneck; one global memory is not the proposed design.

Two versions are not automatically enough: a version lives until its last reader releases it, and legal current/successor traffic must not overwrite it. A source-owned lease, explicit retirement or a proven phase boundary is needed. Include version selection, lease validation and release acknowledgments in the dependency ledger so distributed payload storage does not inherit a new shared control bottleneck. Failure, phase cancellation or reset cannot reclaim a version while an issued callback or accepted effect may still reference it; define draining and release ownership while preserving failure precedence. Measure how many boundary exchanges survive a locality-oriented partition and how much internal admission work disappears. If the full port ledger cannot beat existing gather service, stop before implementation.

This is a substantial alternate placement for the same immutable-gather contract. It can combine with A/B, but their savings overlap and must not be added. Its relation to phi is promising only where phi's numerical/update semantics supply the corresponding immutable-version boundary.

## D. Fixed channels and conflict-free service schedules

A closed topology can bind a message class to a destination lane and member slot at elaboration. That can eliminate repeated route decoding, producer arbitration and parts of mailbox admission. Preserve validation at external/irregular boundaries; internal narrowing requires established provenance. Inspect optimized RTL first: unused header bits that XLS already removes offer no saving. Identify the decode, dynamic actor selection or mailbox-order work that actually disappears; a captured message class alone is insufficient if the same wide metadata validation remains downstream.

A static bank/lane assignment is less restrictive than a global time-division calendar. A valid-bit slot can wait for a late neighbor without assuming synchronized Ethernet arrival. If a local cyclic service schedule is useful, skipped slots must not block unrelated lanes, and queued work must retain sender order, fairness and capacity guarantees. Count worst legal bank conflicts, not only the observed geometry. Color the complete access graph, including collector reads, retirement and debug access.

The recent balanced grouping saved only 2.18% of cycles while increasing cross-group edges from 42 to 50. Separately, the six-bank conditional replay advances the final collection by only 2.04 clocks on average, at most five, while freezing source/consumer boundaries; other policies invalidate those boundaries. These are different probes, and neither substantiates a large whole-round banking gain. This option becomes substantial only when static ownership **removes generic arbitration/control** or enables the versioned storage above. It should be priced jointly with tile partitioning, not pursued as another independent banking knob.

## E. Algorithmic sparsity or parallel windows, if the mapping ceiling remains too low

Two genuinely different workload directions remain available, but neither is a free optimization of the current decoder.

- **Incremental active work:** enqueue vertices/edges whose relevant state changed instead of scanning/exchanging a dense phase everywhere. Stable numerical values do not imply no work: epochs, edge replicas, shifts, correction retirement and busy detection still change. Define the dirty closure and termination detector, retain dense fallback for bursts, and compare full state and ordered corrections against the reference. Retain synchronous epoch snapshots and fixed merge priority; an asynchronous worklist is a different algorithm. Queue duplicates, skew and high-error clusters may erase savings. The recorded 128 sheets contain 546 snapshot generations, of which 512 are mandatory and only 34 are extra merge work. Sparsity must avoid mandatory dense scans, not merely their relatively few repeats; low error rate alone is insufficient evidence.
- **Independent spatial windows:** exploit the accepted average-throughput objective by overlapping genuinely independent windows, rather than filling one sheet's pipeline with more actors. This needs commit/halo geometry, per-site ordering, seam validation and a temporal dependency schedule. Successive sheets of the existing decoder share state and cannot simply round-robin across replicas. Charge halo duplication, all repeated computation and output reconciliation. The eventual roughly 9-wide commit / 18–19-wide enclosing window is a planning scale to verify, not a current benchmark.

These directions may have greater scaling leverage than squeezing D3, but introduce algorithm/application validation work. Keep them behind a demonstrated lower bound or an unfavorable first architectural screen. Do not change phi update order, precision or iteration count merely to obtain easier hardware; the previous discussion explicitly rejected that trade.

## A bounded decision process

1. **Inspect, without another optimization:** augment the existing physical report from the retained #65 checkpoint with owner identities, path-cell locations, net fanout/load extent, memory locations and congestion. Compare the six replicas and request/mailbox competitors. This distinguishes long crossings, congestion, high fanout and deep local logic; “wire delay” alone does not. Extend the existing report, not another profiling framework.
2. **Specify the control boundary before implementation:** for the selected resident/regular region, draw before/after register-dependency graphs and record the minimum same-cycle inputs for readiness and commit. Include faults, ownership, credits and reverse acknowledgments. State actor population, accesses per clock, crossing widths/rates, versions, issue capacity and recurrence latency. A proposed stage needs a cycle/throughput budget; a proposed local predicate must not wait for the wide result it is meant to avoid. Versioned-neighbor redesign remains deferred.
3. **Verify and route one representative connected probe:** the soft-grouping trial is complete; next test the smallest region with a changed control dependency. Check the intended removal in optimized IR and mapped paths, including alternate starts, and recheck it after area sharing. Register cumulative capacity, a routed-period/step target and stop conditions. Compare readiness, admission, collection, mailbox, RAM and controls together; target a shared subpath or give surviving competitors an explicit treatment before a full-core run.
4. **Qualify and integrate only after review:** ordinary source/reference agreement, protocol faults/stalls, logical debug, mapped resources, full cycles and finally matched routing. One paired physical run screens a large effect; repeat controls/seeds when variation could change the decision. Require sustained independently offered load and burst/backlog qualification before claiming 1 MHz.

Complete the receiver model's missing controller-commit observation only if using it for that decision. It currently rejects the balanced capture because two writes occur three clocks later than modeled; retained baseline replay is exact, but counterfactuals with frozen arrivals cannot establish whole-round gains. A coupled service model needs producer/consumer feedback and recurrence ownership, not subtraction of profile wait spans. This limitation need not delay a same-RTL physical-locality screen.

Keep actor identity, phase/epoch, failure reason, waiting members, accepted work and in-flight ownership available through the debug catalog for every new placement. A physical tile need not be an Erlang process, and an Erlang process need not own an entire physical execution engine. Queries must reconstruct a coherent logical actor commit, including phase/epoch and source attribution; independently owned banks must not expose a mixture of pre- and post-callback state. Label in-flight work rather than forcing all implementation state into a universal wide record.

## First boundary experiment: reserve before loading

The loader currently expands a reserved ticket into `MachineBits` + ordinary frame + indexed snapshot payload/progress, then retains that expanded value in a stage and FIFO before execution. Move those two storage boundaries ahead of the reads. Keep the loader and executor separate, with a depth-zero response handoff. Do not replicate actor context or retirement logic.

Ownership/access ledger: the service reserves the actor and completion slot, owns all three write ports and mailbox ordering, and releases the reservation only at retirement. The loader exclusively owns the three read ports; the gather lease protects its row until retirement. The executor consumes one loaded activation and emits one result. The result FIFO plus skid retain one result per actor. Moving ticket storage changes neither memory transactions nor port count; it removes capacity for *loaded* requests, so blocked responses and simultaneous issue/retire require explicit tests. Actor state/debug RAM layout and failure precedence stay unchanged.

Preregistered expectation: 3–7% fewer complete-core LUTs, unchanged BRAMs and cycle count within ±1%. This is an area/placement experiment, not a clock-gain promise: removing request buffering may expose a response-ready path, while unrelated service/router paths still compete. Price connected six-actor domains at both 19 and 22 producers, then the complete 128-sheet decoder; reject area growth or cycle regression beyond 1% absent a demonstrated routed-throughput trade. The timestamped plan and all measurements live in `hls_artifacts/runs/resident-operands-2026-10-04/`.
