## Decisions from the discussion

- Stop cycling through small variations of the same general scheduler pipeline. More actors can fill it, but also increase work per sheet; utilization alone is not success.
- Target sustained sheet completion and stable backlog. Corrections need ordered site retirement, but a fixed maximum correction delay is not currently a requirement. Count empty corrections as completed sheets.
- Once the chosen workload supports 1 MHz round resolution, prioritize smaller area over additional rate. Preserve measured capacity to absorb bursts; mean service below one microsecond alone does not establish adequate finite queues. Storage changes require a demonstrated area, capacity or access bottleneck.
- Preserve phi's algorithm and physical-quality problem. Fewer rounds, weaker precision or asynchronous phi updates are outside this campaign.
- Treat actor granularity, storage ownership, schedulers and placement as provisional. Concentration, halo replication and physical locality form one tradeoff study with explicit total-work and resource costs.
- Investigate conflict-free schedules as checked implementation information that ERTS may ignore. An actor topology alone does not remove BRAM port conflicts.
- Prefer compiler inference of regular phases. Wildcard message matches can simplify source, but must respect the finite receive domain, ordered guards and existing malformed/stale-message failures.
- Separate demo-hardware limits from mapping limits with a matched UltraScale+ comparison before investing in another architecture.
- Preserve causal dependencies separately from observed scheduling. Use resource and recurrence bounds to select experiments; neither good utilization nor a shortened isolated path establishes application throughput.

## Objective and controls

- Sustain one incoming syndrome sheet per microsecond without secular backlog growth. Correction latency is measured, but a hard per-correction deadline is not presently required.
- For a fixed supported window and workload, reduce LUT/FF/BRAM/DSP demand while retaining that service target and adequate burst margin. Report remaining FPGA capacity for other experiment components; higher peak decoder rate is not an end in itself. Faster clocks remain useful when they enable fewer engines or other area savings at the required service rate.
- Study supported spatial window extent separately from retained time depth, boundary/overlap state and CSS-sector count. Moving d=3 to d=5 grows both spatial size and time depth; it is not a pure widening experiment or an implemented spatially parallel partition.
- Drive arrivals independently of decoder readiness. Count accepted, completed and pending sheets; retain correction order per site and the finalized horizon. Queueing must not conceal discarded work or an ever-growing lag.
- Report backlog trajectories, service rate, latency distributions, storage high-water marks and overflow behavior. Finite experiments provide evidence of stability, not a guarantee for every noise history; average utilization below one is necessary but not sufficient.
- Keep the physical 4×2-qubit acquisition patch and the total compute, memory and link budget explicit. Decoder placement can differ from acquisition placement. More concentrated work receives no unaccounted processors, ports or bandwidth.
- Preserve the original workload/noise controls in each A/B comparison. Decoder alternatives additionally need quality measurements; matching today's short demonstration is insufficient.
- Separate simulation clocks from qualified physical timing. Run the [UltraScale+ comparison](../experiments/07-openxc7/yap/ultrascale-comparison.md) alongside this work before attributing a clock limit to the architecture alone.

The [completed native device screen](../docs/artifacts.md#historical-reports) (`experiments/07-openxc7/results/technology-comparison-2026-09-27.md`) found 40–51% shorter replay periods on UltraScale+, with pipeline rankings reversed after routing on both tested grades. Both complete-tile attempts hit the synthesis time limit. Use these as target-selection evidence, not a full-tile 1 MHz result or a calibrated Snowflake clock.

Reusing a read requires the same value version, not just the same address. Compare complete states after every phase before counting savings; growth ownership is a separate change.

## 3. Test conflict-free bank ownership

The current distributed reduction plane already collects independent source lanes outside actor RAM and sends one aggregate to the scheduler. Contributions are not competing read-modify-write updates to actor state. [Collector generation](../src/hls_partition_reduction_dslx.erl); [placement checks](../src/hls_partition_reduction.erl).

- [ ] Derive possible producers, destinations and phase-local accesses from a closed topology; allow checked placement hints where inference is insufficient. ERTS can ignore these hints because they select a legal implementation, not different callback behavior.
- [ ] Construct a conflict graph and compare 1/2/4/8 storage banks against actual bursts and worst-case allowed concurrent accesses. Count read and write ports separately.
- [ ] Store raw ordered fragments with epoch metadata rather than reverting to one shared accumulator. Verify bank ownership before claiming concurrent writes; one bank per direction does not automatically exclude competing producers.
- [ ] Evaluate static bank ownership separately from timed service classes. Eliminate an arbiter only when ownership makes contention impossible; a fully dynamic fallback usually retains the arbiter and mux.
- [ ] Synthesize only candidates whose service model preserves useful throughput and whose storage/mux reduction is substantial. Start with the bounded-neighborhood kernel; retain phi as a regression/control rather than assume it benefits.

**Activation gate:** pursue this bank-ownership work only when a required window exposes a measured resource problem or a concrete area-saving opportunity while preserving 1 MHz service.

**Hypothesis:** checked ownership can make larger bounded windows affordable by replacing replicated queues/selectors with banked storage. It may give little benefit for four actors with shallow queues. Measure area and port service first; do not forecast whole-design frequency from bank count.

Do not introduce a globally timed Ethernet calendar. Local schedules must tolerate late arrivals, preserve per-source order and retain accepted work under backpressure. Do not hold a service class waiting for a remote input when another class is needed to make progress. Specify bounded service for ordinary traffic and preserve complete-population failure draining.

## 4. Census regular phases before specializing them

- [ ] Derive a phase summary from the compiler's closed message union: handled tags, unconditional postponements, reductions, state fields read/written, effects and possible next phases. Unknown guards or effects remain unknown.
- [ ] Permit wildcard postponement only as a source-level simplification over that declared input union. Preserve clause order, unmatched/invalid-input errors and explicit failure behavior; do not turn malformed traffic into an indefinitely retained message.
- [ ] Compare generated source and phase summaries before/after the catchall change. Cleaner source does not itself establish fewer mailbox scans, RAM accesses or hardware branches.
- [ ] Identify a regular phase whose prerequisites and state ownership permit a locally reserved transaction. Reserve state access, execution and result/publication capacity before starting; remote arrivals remain outside that internal schedule.
- [ ] Count exactly which general selections or RAM visits disappear. The current scheduler already reserves actors and completion/outbox capacity; repackaging the same reservations is not an improvement.
- [ ] Use ideal local-phase service in the validated complete-system model to bound potential savings. Only then design an implementation, possibly retaining narrowly owned state across a regular loop.
