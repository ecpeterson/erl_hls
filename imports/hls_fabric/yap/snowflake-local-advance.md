# Local phase advancement probe

Base: `ba1027a`. This isolated ERTS-only experiment retains the ordinary actor implementation, numerical kernels, complete snapshot exchanges, correction ownership and eight-credit host interface. No XLS or native build is part of this first test.

Hypothesis, registered before edits: replace the global barriers after drop, whole growth and half growth with local `next_event` transitions. Keep `ready` entry so that drop corrections publish before local advancement. Keep global busy decisions after whole and half merge. For D3/H3, remove three global quorums, 108 vertex completion messages and 18 aggregate messages per sheet. The 108 internal continuations replace 108 phase-message activations; they do not by themselves save vertex activations. With `r` repeated merge phases, command deliveries change from `36*(5+r)` to `42*(2+r)`, saving `96-6r`. No cycle, frequency or area percentage is predicted.

Collectors receive the same root phase command as vertices and derive its exact terminal epoch/kind: drop→whole merge, half growth→half merge, or the commanded merge itself. They never infer a global busy decision from their local group. Before a command arrives, only completions consistent with a legal successor command may wait; the command then fixes the one valid terminal epoch/kind. Wrong or stale epochs and duplicate/nonmember sources still fail. Arithmetic on epoch tags wraps modulo 2^32.

A vertex can receive a next-phase snapshot while still dropping or collecting growth snapshots. It must retain that immutable snapshot until the exact successor phase. Its neighbor cannot send a later merge transfer before receiving this vertex's next-phase snapshot, so there is no unrestricted future queue. Initial bound: six current snapshots plus six successor snapshots plus a phase command is at most thirteen mailbox entries (capacity 24). During drop, one shift may race six next-phase snapshots; configured vertices may see that same race before their initial command. Collectors can hold six early completions plus one phase command (capacity 8). These arguments assume valid per-peer protocol traffic, not arbitrary duplicate flooding; rejection tests must challenge the boundary and rollover cases.

Validation: compare every stable vertex/edge state and ordered correction with the independent reference, named and enumerated fixtures, credited streams, delayed neighbor/collector/command delivery, and explicit wrong-epoch/duplicate/membership cases. Use ordinary behavior debug mailbox information when a run stalls. BEAM elapsed time does not predict FPGA cycle savings.

## ERTS result

The prototype preserves every named/enumerated reference stream in flat and tree6 configurations, the 128-sheet 0.5% stream with eight outstanding inputs, and delayed neighbor, collector and root-command deliveries. Directed checks exercise six queued successor snapshots, five peers reaching merge while the sixth is still in growth, duplicates, bad source membership, wrong epochs, and collector epoch rollover. The ordinary variant retains its 46 actor/vertex/barrier/coordinator checks. This is finite regression evidence, not formal equivalence.

One extra legal race emerged: after half-merge publication, a neighbor can receive the next sheet's drop command and emit its growth snapshot before this vertex receives that command. The vertex permits exactly that one-ahead snapshot while awaiting the command. A repeat-half-merge command instead makes the retained tag invalid, and replay fails. No arbitrary future epochs are accepted. The same 13-entry conservative bound covers this command/shift/snapshot race; collectors retain at most six early reports plus their command. Incorrect alternate outcomes can wait only until the root command disambiguates them.

For the pinned 128-sheet workload there are 34 repeated merge phases (0–3 per sheet). The graph therefore changes phase deliveries from 24,264 to 12,180, removes 13,824 vertex completion messages and 2,304 collector completion messages, and substitutes 13,824 internal events for the removed vertex phase-message activations. These are protocol-derived counts using the unchanged reference phase sequence, not observed FPGA cycles. Each internal event still occupies an actor activation; shared scheduling and entry publication can absorb some of the transport savings.

Reproduce the ERTS variant with `python3 experiments/snowflake/actors/run.py --local-advance --stage FRESH_DIRECTORY`. The switch defaults off; it compiles the same ordinary actors and selects the local-advance test module alongside the reference stream tests. `delay_phase_recipient` in the BEAM runner delays one command target while independently routed peer traffic continues. No host logic advances decoder phases.

Retained local evidence: `_build/local-advance-final2/{checks.json,tests.log,dialyzer.log,source-contracts.log}` and `_build/local-advance-default-final2/{checks.json,tests.log,dialyzer.log}`. Dialyzer checks all eight actor/reference/runtime modules in each compiled mode; intentional invalid-call EUnit modules are outside this scope. The input/source/beam identities are recorded by `checks.json`. Hardware lowering and measurements are the next gate, before treating the variant as an improvement.

## Hardware result

The same two-stage XLS schedule compiles the variant. Against the combined control/effect/growth implementation, every one of the 127 measured output intervals saves 110 clocks: minimum/mean/maximum 365/400.763780/737, population variance 7742.353649, versus 475/510.763780/847 before. All 1,125 correction frames and reference rounds pass, as does an output-stalled control. This is a 21.54% mean cycle reduction, not yet a physical step-rate claim. Matched native implementation uses the same completion-FIFO storage on both sides.

The stress-eight passive profile shows 10,752 activations, up from 10,572: early transfers account for 180 postpone/retry visits. Removing global waits helps despite those extra visits. The accepted internal event still uses the ordinary actor scheduler; no unobserved host work advances a phase.
