# Source-protocol generation

`hls_protocol_transport` prepares source programs and receiver ownership through [protocol planning](../../../planning/protocol/README.md). `hls_local_actor` composes `xls_activation_codegen` with `xls_local_owner`; activation reuses [shared machine execution](../execution/README.md), while the local owner supplies receipt/action and clock ownership. `xls_protocol_inbox` installs the checked receiver layout.

Network, boundary, application, bridge, deployment and mixed builders compose larger bundles from the retained transport plan. Their `xls_protocol_*` helpers render compact codecs, links, ingress, arithmetic groups and wrappers; associated pins use the [Verilog adapters](../../sv/README.md). These are related composition stages within one backend, not separate packages or interchangeable execution modes.

Preserve emitted failure codebooks when composing actors. Planning and emission do not attach host sessions; runtime clients consume the resulting descriptors separately.

The optional [observation application](../../../../../hls_spacetime_observer/README.md) binds passive simulator taps to an exact emitted build; its capture adapter produces cycle events for offline consumers. See [passive capture](../../../../../../docs/spacetime-capture.md). These diagnostic observers generate no synthesized trace hardware and make no physical timing claim.

`hls_protocol_domain` composes a closed network with the compiled runtime lifecycle kernel, incarnation gates and actual reset/initialization completion. Its explicit partition API requires an external crossing owner. `hls_protocol_domains` supplies that owner using one compiled `hls_domain_channel` policy and payload register per directed cut; placement checks require each cut to stay inside a declared restart group. Groups specify recovery scope, not automatic supervision. See [recovery domains and crossing mailboxes](../../../../../../docs/domain-recovery.md). The lifecycle and channel kernels supply their own compilable service entries, so hardware and ERTS use the same finite decisions.

`hls_protocol_supervisor` places a compiled static supervisor above independent domain cores. A checked ordinary OTP declaration selects one-for-one policy; the hardware binding supplies each child network and local clock rate. The supervisor alone issues child lifecycle commands, using a finite delegated identity interval. Its management scan does not carry application traffic. Raw and framed compositions retain independent child application interfaces. The framed boundary watches exact incarnations and retains their retirement records until the host has drained prior output; the parent's management scan carries no child application messages.
