# Application timing coverage campaign

Acceptance: the 2×1-per-plane testbench must generate RTL with the calibrated estimator, without unit fallback. Audit every optimized IR node, retain the resulting per-proc schedules, and check the assembled mapped core separately. The same tools accept larger optimized IR packages; application-specific evidence belongs beside each application.

Measure a bounded neighborhood, not just observed selector shapes: wider payloads up to 1024 bits, selector fan-ins around powers of two through 32, default-arm and array indices through 64 bits, variadic logic, wide comparisons, variable shifts, and nested array reads. Choose exact additional cases after the complete IR audit. Zero-bit values and demonstrably equivalent one-case selections need semantic handling, not invented physical measurements. Preserve underestimation statistics and held-out shapes.

Preregistered expectations: closing coverage enables scheduling but does not imply a whole-core frequency win. Compare identical stage count/II and streamed behavior; independent operation costs still omit proc-to-proc ready paths and global placement. Measure composed controls alongside arithmetic. Anticipate scheduler replication, mailbox/outbox capacities and registered FIFO boundaries by varying width, fan-in and index width independently.

After vendor measurements are retained and both applications compile: test payload writes on accepted empty-queue bypass (no observable latency change; expected targeted-path saving 5–8 ns, whole-core 0–10% step-time improvement), then a depth-one one-slot FIFO specialization (same throughput/handshake; expected roughly 600–850 FF and 1–3% core LUT saving for the two wide phi egress queues; whole-core timing uncertain). Validate FIFO traces including simultaneous pop/push, stalls/reset and capacity behavior before application routing. Gains are hypotheses, not cumulative promises.

Additional vendor evidence: DSP input/M/P register combinations and variable-address SRL16E/SRLC32E fixtures. Retaining these arcs anticipates arithmetic pipeline cuts and alternate FIFO storage; collecting them does not qualify those modes in the native timing implementation.

Refined before implementation: the fresh small-core RTL has 40 depth-one FIFO instances totaling 9,832 raw payload bits, including compiler-created pipeline queues. Specializing every valid depth-one configuration may therefore remove roughly 5,000–8,000 mapped FF after constant folding, substantially more than the two 424-bit egress queues alone. Measure the targeted pair separately from the full materialization change; preserve throughput and report placement variation.

FIFO experiment checks: preserve the generated module interface and the `slots` occupancy name. The topology-debug adapter currently proves occupancy through a registered `slots` value and its full comparison; a one-bit depth-one occupancy may make that comparison an alias. Check and, if needed, narrowly extend that structural validation. Use the existing FIFO interpreter oracle across all valid configurations; depth one already excludes registered-pop configurations. Splice only changed FIFO module definitions into a retained application RTL when isolating the experiment from unrelated generated naming changes.

Qualification refinements: require pin/parameter equality after routing as well as import; disable placement-time replication and buffer insertion. The 32-entry, 1024-bit updates with 32/64-bit indices exceed the exact part’s LUT capacity; retain those failures and measure 512-bit boundaries instead. A supported 1024-bit payload does not imply support for every fan-in/index combination.
