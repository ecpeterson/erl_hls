# Retargeting the timing experiment

The current workflow is repeatable for `xc7z030sbg485-1`, but changing targets requires source edits. First make another 7-series part or speed grade configurable; broader family/vendor support should follow only when exercised by a concrete target. This is planned work, not an available interface.

- [ ] **Define one target profile.** Record part/package/speed grade, synthesis backend and options, clock period/site policy, I/O constraints, native chip database and tool identities. Keep probe selection, training/held-out widths and implementation repetitions explicit. Carry the profile fingerprint through every manifest and model; reject mixed-target or mixed-flow evidence.
- [ ] **Remove scattered target assumptions.** Pass the profile through probe/pipeline preparation, `measure.tcl`, analysis and reporting. Parameterize native comparison constraints as well as the chip database. Separate reusable IR generation, fitting and streamed-result checks from family-specific register wrappers, primitive import rules and timing extraction. Generalize the XLS estimator's target selection without silently accepting a table for another profile.
- [ ] **Add a resumable campaign command.** Orchestrate preparation, vendor-host measurement, collection, fitting, pipeline validation, native comparisons and reporting. Retain bounded concurrency/timeouts and explicit failure records. Reuse a phase only when its inputs, profile, scripts and tools match; include tool identity and constraints in the current batch fingerprint. Keep transfer bundles independent of SSH host names and credentials. Preserve compact evidence while pruning disposable checkpoints.
- [ ] **Generate target-specific model data.** Emit XLS costs and native primitive delay tables from audited measurements instead of hand-copying constants. Keep reviewed adapters for primitive modes, pin/clock associations and edges; new numerical rows do not establish support for an unfamiliar mode. Preserve exact-target guards, reject unsupported shapes and report missing endpoint/internal timing checks separately. Installing new calibration must not change compiler defaults.
- [ ] **Qualify the interface on a second target.** Start with register, carry, mux, RAM and DSP probes to verify import, clocks and supported modes; then run the full corpus and equal-latency/II pipeline comparisons. Require no source edits for the second supported 7-series profile. Report underestimates, pessimistic errors, area and scheduling regressions; retain held-out tests and measure placement variation explicitly. Test interruption/resume and deliberate profile/tool mismatches.

A later FPGA family or vendor needs a reviewed mapping/timing adapter and applicable RAM/DSP mode definitions. The campaign runner and operation tests should survive that change; primitive interpretation and clock qualification still require engineering judgment. SDF extraction alone cannot certify those meanings or replace design-wide timing validation.

Completion means a user can select a supported profile and explicit tool paths, run/resume the campaign, and obtain a qualified-scope report and installable calibration without editing Python, Tcl or C++. It does not mean measurements become instantaneous or that every resulting model establishes a safe board clock.
