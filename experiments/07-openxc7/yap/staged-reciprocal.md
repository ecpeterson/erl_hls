# Staged reciprocal screen

Registered before implementation on `566b3d3`. The rounded division in the measured recurrence is a signed 37-bit numerator times `ceil(2^41/12)`, followed by a half-unit bias and arithmetic shift. Three DSPs occur in series on the retained physical path; their cell arcs alone exceed 5 ns.

XLS's present `DefineSmulpFunction` emits a whole multiplication, then represents it as a constant offset plus product-minus-offset. `MulpCombiningPass` rejoins an adjacent sum. Merely scheduling that operation separately from its final addition does not expose the desired internal multiplication cuts.

The candidate splits the numerator into an unsigned low 24-bit limb and a signed high 13-bit limb, and the reciprocal into 17/17/4-bit limbs. Register six independent narrow products; reduce their aligned sum plus rounding bias with carry-save operations; register the remaining two rows; finish with a carry-propagating addition and quotient slice. This is an isolated, fixed-width arithmetic experiment, not a new actor or a change in application precision.

Expect at most one DSP on any combinational path after mapping. Budget three arithmetic stages at II=1; the complete recurrence also needs operand preparation and saturation, so this is not a three-cycle whole-actor forecast. Report registers, DSPs, carry cells, LUTs and the longest DSP chain against the unsplit operation. Check signed extremes, half ties, limb boundaries and deterministic random inputs against independent integer rounding; these are simulation witnesses, not an exhaustive claim. Do not expand formal-method work on this turn.

Require register cuts to survive synthesis and reject a candidate if recombination restores a serial DSP chain. The previous 8 ns isolated-stage target remains a design target, not a prediction. Native timing lacks required registered-DSP coverage; retain an exact vendor measurement bundle if that mode appears, without claiming a routed speedup or restarting EC2. Integration remains conditional on measuring the feedback-latency ledger and preserving one owner of field state, same-actor exclusion, completion capacity and publication order.

Separately, retirement updates only the retiring actor's candidate row, which the existing same-cycle fallback excludes. A selector could use the pre-retirement candidate rows while retaining new aggregate capture, current credits/global busy state and the same exclusion/cursor. This proposes identical eligible actors and grant, not one-cycle-stale arbitration. Retain the post-retirement state for admission and subsequent selection. Do not implement this shortcut during the arithmetic screen.

The first mapping screen achieved the structural target but failed mapped simulation. One independent failure drops enables during SRL extraction; use the complete-core flow's existing `-nosrl` on both probes. The staged candidate also fails after DSP-register absorption, reproduced by two registered products sharing a signed operand. Keep that failure and try the candidate with `xilinx_dsp.multonly`, which preserves explicit fabric stage registers. This is a candidate-specific synthesis policy, not a proposal to change global application mapping. Require mapped simulation before measuring it.

The fabric-register variant permits a covered native timing screen if the mapped-mode audit confirms all DSP registers are disabled. Prepare matched native launch/capture harnesses and route one seed initially. The expected mechanism is demotion of the multiplier cascade; there is no whole-core speedup threshold. A remaining recombination/enable path may replace it. Preserve any demonstrated path improvement even if another core family or additional application latency prevents an immediate step-rate gain; price the combined changes later.
