# D3 decoder XC7Z100 baseline

This measurement uses the [D3 physical benchmark](../phi-timing.md) on `xc7z100ffg900-2`: two phi planes, three scheduler shards per plane, two XLS pipeline stages, II=1, the `unit` delay model, and deterministic syndrome replay. The application source is unchanged from `d62c66f`; the benchmark implementation is identified in the [machine-readable report](d3-2026-09-12.json). This is the decoder-only workload with a small clock/activity harness, not the full phenomenological memory experiment or a board design.

## Modeled timing

**These are partial-path estimates, not safe clocks for the complete decoder.** The pinned backend excludes sequential timing for all 90 RAMB18E1 and 22 RAMB36E1 instances. Its 144 combinational DSPs use coarse input delays; register checks use fixed 0.1 ns values, and the shared Zynq timing tables do not select the requested speed grade. The [timing-model audit](../phi-timing.md#measurement-limits) identifies the implementation and omissions. Changing timing coverage can invalidate a frequency comparison.

All three seeds route successfully, but miss the requested 100 MHz constraint.

## Paths to investigate

Seed 1 starts at the X reduction plane's output cursor and reaches the selected contribution-key comparison. Seed 2 starts at the same X-plane cursor and reaches queue-bank next-value logic; seed 3 follows the corresponding Z-plane path. The cursor is `u32` although D3 scans only nine slots. Its wrapped-candidate scan, slot selection, and subsequent frame processing form a substantial combinational network. In seed 1, the `output_ready && output_slot == 1` net feeds 747 mapped input ports and contributes a reported 17.8 ns routing segment.

Seed 2 begins at cursor bit 6. The source initializes the cursor to zero and updates it only to a selected slot's successor modulo nine, so that bit remains zero under the source-level invariant. The timing analysis does not use that invariant. A narrower type can expose the bound to synthesis; the benchmark does not prove functional sensitizability of every reported path.

Narrower bounded cursor types and a different selection network are concrete optimization candidates. They still require fairness, functional, cycle-count, area, and routed-path comparisons. Placement quality also matters: the backend performs post-placement repairs of stranded clusters/cells, recorded per seed in the JSON. These measurements do not isolate an RTL cause from placer/router limitations.

All 6,480 warnings per completed run concern unconnected DSP cascade outputs; the JSON groups them without discarding their counts or examples. No routing errors or ignored combinational loops are accepted.

## Validation and reproduction

The public-port harness verifies status/correction framing, stall stability, all nine coordinates on both planes through step 32, and nontrivial corrections. With variable sink readiness it takes **175.958333 cycles/step** between steps 8 and 32. This stimulus-dependent logical result must not be combined with the partial-path MHz to claim deployed throughput.

The same RTL passes the production topology-debug query check: 254 channels and 88 FIFO occupancies are discoverable; 10 full-FIFO seeds lead through 98 adaptive queries to the deliberately blocked `x_decoder_event` sink. After release, 66 queries find no channels blocked on both visits. Original and instrumented public outputs match for 3,200 cycles, and structural noninterference passes. The physical run measures the uninstrumented decoder; it does not measure debug overhead.

The 698 EUnit tests and eight benchmark tests pass, including a real small Yosys mapping/assembly check. [CI passes for the benchmark implementation](https://github.com/ecpeterson/erl_hls/actions/runs/34672726878). Native D3 conversion, optimization, code generation, simulation, and all physical runs are separate completed experiments.
