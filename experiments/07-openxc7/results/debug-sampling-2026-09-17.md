# Continuous passive sampling during debug queries

The production boundary monitor admits one complete request and waits for its reply's final accepted beat before admitting the next packet. This keeps query backpressure from reaching passive application sampling. Partial and malformed packets still drain through `TLAST`, and reset aborts an unfinished transaction. The debug wire format and application datapath are unchanged.

## Regression and proof

The motivating counterexample holds the final beat of an error reply and offers `GET_COUNTERS` while the request port is not ready. Without the admission fence, a later XLS server activation can send its snapshot request before the earlier reply retires. The observer then waits for snapshot acceptance and rejects new samples. Application traffic itself continues. The public counter reply reports 95 missed observations in the retained 96-cycle-stall regression. Holding just the first reply beat does not exercise this overlap.

`tools/test_debug_sampling.py` proves that `hls_debug_capture.observation_ready` is true on every non-reset cycle after a sampled shared reset when the production tap continuously offers observations. It analyzes the actual generated two-stage Observer and three-stage, II=2 DebugServer, the snapshot-request register, the admission fence, and the trace store. ABC PDR establishes unbounded safety. Observation contents, all query signals, reply readiness, and subsequent resets remain arbitrary: the proof does not assume well-formed requests, stable stalled input beats, or eventual readiness. The one-clock synchronous-reset composition is the proof boundary.

Two negative controls must produce counterexamples: removing the admission fence, and allowing debug reply backpressure to block trace writes. The first also fails a ready/valid-compliant public-port simulation with the missed-sample count above. The corrected design passes overlapping counter, trace, and error replies; stalls at both header and final beat; exact frozen-bank readout while the other bank fills; trace overflow; rejected and unterminated packets; and reset during a stalled reply. A separate live `hls_debug` regression still detects injected gaps and validates per-stream framing recovery.

This proof establishes sampling acceptance, not all counter/trace values, query liveness, application packet conservation, CDC safety, or timing closure. Reply-level simulations cover the specified counter/trace behaviors. Trace capacity remains finite: overflow drops events even when no observations are missed. Gap reporting remains part of the interface for alternate providers and fault injection.

Native validation passes 1,102 EUnit tests and the complete D3 public-debug regression on Icarus 12. D3 inspects all 54 actors, follows seven full queues to the external sink, accepts 512 application beats during a held debug reply, and matches the ERTS result. Its production reference and instrumented application outputs agree for all 14,405 clocks of that run. That elapsed count depends on host-driven stall release and is not a throughput benchmark. The existing validated application build is reused; only the monitor shell changes.

Run the proof and simulation against the production debug RTL generated by `tools/remote_xls_sim.sh` or `tools/build_phi_debug.py`:

```sh
python3 tools/test_debug_sampling.py _build/xls_sim/regsvc --yosys "$YOSYS"
python3 tools/test_debug_trace_integration.py _build/xls_sim/regsvc
```

The proof uses Yosys's bundled `yosys-abc`; no additional solver dependency is required. Commands, input/tool hashes, AIG models, negative-control witnesses and logs are retained under `_build/debug-sampling`. CI reuses its existing generated RTL.

## Mapped area

The prediction registered before synthesis was one extra control flip-flop, a few additional LUTs per boundary monitor, unchanged RAM use, and unchanged application behavior in cycles. Admission reopens one cycle after a reply's final accepted beat; serialization and wire contents are unchanged.

Two matched naming seeds compare the merged `bb46aad` baseline with the fence using identical native generated observer/server RTL. The measurement includes the complete routed boundary monitor: tap, collector, counters, trace store, and serializer. It excludes application logic, application RAM, topology queries, and shared debug transport. Yosys 0.69+10 (`370a53acf-dirty`) runs XC7 ABC9 mapping with no I/O or clock buffers.
