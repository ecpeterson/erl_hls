# OTP umbrella Stage 5

Stage 5 turns the Stage 2 model and Stage 3 application graph into one measured optimization loop, then cuts maintained public use over to the umbrella. It does not import external experiment source or history, collapse application boundaries, or make runtime depend on synthesis or optimization.

## Identity and cache contract

The retained chain is:

`logical system → proposed plan → frozen source recipe → build request → exact products → realized implementation → evidence/characterization → revised plan`

- Logical-system identity covers the canonical materialized topology.
- A plan binds that logical identity, exact actor placement and schedule, constraints, capabilities and optional parent-plan/characterization provenance.
- A frozen source recipe binds every generated or copied input independently of its checkout location.
- A build request binds the recipe, selected target policy, tool identities and arguments. It does not predict generated bytes.
- Product identity binds the exact retained output inventory. Request and product identities stay distinct because external tools may be nondeterministic.
- A realized implementation binds one plan, one request and one product set. Evidence is reusable only for that implementation identity.
- A characterization binds both plan and realized implementation. Revision rejects mismatched evidence and records the parent plan and characterization.

The existing stage cache remains the byte store. A hit is accepted only after its request record, complete product inventory and byte digests validate. This establishes reproducible local reuse under the declared filesystem/tool trust boundary; it does not establish source eligibility, semantic refinement, timing closure, authenticity or hardware behavior.

## First feedback witness

Use the maintained `hls_protocol_arithmetic_fixture` with exactly three actors:

- `local3` implements three independent scalar-completion datapaths.
- `shared3` implements one scalar-completion datapath and the existing round-robin selection/return network.

Both candidates come from explicit implementation plans over the same logical topology, target, protocol capability and observable actor behavior. The projection validates exact topology identity, actor coverage, target homogeneity and schedule membership before producing target configuration. Existing SAT and RTL checks supply bounded semantic evidence. One matched default XC7 run per candidate supplies physical resource and timing measurements under one fixed tool, part, clock and directive set; no seed-sensitivity claim is made.

The feedback policy may select sharing only when the stated DSP objective improves without violating setup, hold, pulse or internal timing-coverage gates. That is a two-candidate finite witness of computation/communication co-optimization, not a general optimality, frequency, board or sustained-service claim.
