## Boundary observation

The original eight-sheet stress recording has 11,148 vertex activations, including 4,896 snapshots and 3,264 transfers (73.2% together), plus 576 growth completion-only activations. This is a different cohort from the 128-sheet service comparison. All observed dispatch-ticket→executor-request intervals are three clocks, and all executor-request→accepted-result intervals are one clock (zero variance in both). Result→state-RAM-write varies: snapshots min/mean/max 1/2.1703/12 clocks, population variance 5.2729; transfers 1/1.5686/8, variance 1.3433. Therefore callback bypass alone cannot remove a long arithmetic pipeline; gather savings must come from fewer state visits, fewer ownership cycles or less retirement contention. Serializing ordinary state reads behind classification is a real possible cost.

The passive run checks every request/result identity, written state and published effect batch, and exactly reproduces the external transcript. Its reusable producer is `channel_probe.py --activations`; `channel_profile.py` renders these boundaries and ownership intervals with the existing common SVG/Perfetto renderer. Frozen local evidence is under `_build/snowflake-control-compaction/baseline-dispatch`. Ownership intervals include waits and are not evidence of continuous computation. Initial state writes are excluded from activation counts.

The retirement extension binds each scheduler's actual enabled `in_flight` register clear from its generated state layout and RTL assignments. In the same 11,148-activation baseline recording, 11,001 ownership releases coincide with the state write; 54 follow it by one clock, 78 by two and 15 by three. Every effect-producing activation releases ownership at accepted batch publication. Thus a RAM write alone is not the end of an owned activation. Fold-only projection commits can now be observed without inventing state writes. The new capture, still exactly equal to the external transcript, is `_build/snowflake-control-compaction/baseline-retirement`; focused exports retain the full-run statistical summary.

## Coordinator carry attribution

The unchanged ZU7EV-2 core synthesized at a requested 5 ns has a 7.971 ns worst setup-adjusted period: 7.816 ns data path, comprising 2.206 ns cell delay and 5.610 ns estimated interconnect. It runs from `materialized_fifo_fifo__actor_0_req_/tail_reg[0]/C` to `__snowflake_coordinator__Service_0_next_inst/____state_21_reg/D` (`stepped_admission_valid`), through 41 logic levels including eleven CARRY8 cells. This is synthesis timing, not a routed clock qualification.

Checkpoint connectivity identifies the carry cascade as the startup check `seen bsr Count =:= 0`, not arithmetic on the count. Its first carry (`____state_2_reg[15]_i_640`) starts at constant one; all 88 DI pins are constant zero; its final used output is `____state_2_reg[15]_i_6/CO[5]`. Thus the cascade conjoins 86 select predicates. Its fan-in contains exactly the 256 `____state_5` seen bits and all sixteen count bits from each of the 64 mailbox payload rows. The original generated RTL names the corresponding expression `_7__4`: a 256-bit right shift by the selected configuration count, followed by equality to zero. The `____state_2` names on the mapped cells are not evidence of an adder.

The conceptual chain is incoming FIFO selection → direct mailbox admission/selection → configuration-count selection → seen-mask validation → handler success/consumption → projected mailbox occupancy → next receive reservation. Although this validation is used only during configuration, it still constrains the common clock. Bounding the root's population and mailbox shrinks both the wide validation and the selection feeding it while retaining all checks. The direct actor's admission dependency is separate from the shared scheduler's physical-slot allocator.

Local evidence is `_build/snowflake-control-compaction/coordinator-cone/`: `query-deep.tcl`, the extracted mapped coordinator, `cone.tsv`, `leaves.tsv`, `timing.rpt`, and `attribution.json` with source/report hashes. The query only read the existing baseline checkpoint; it did not synthesize a new variant or alter the concurrent implementation run. This attribution establishes the present cone, not the next limiting path or the eventual placed improvement.

## Remaining representation work

The vertex has 172 configuration bits written only by geometry/configuration callbacks: source/id, neighbor/syndrome/retirement masks, height, four geometry flags and three signed translation constants. The mapped state banks consume 60 BRAM36s, versus 12 for payload mailboxes; the wide, shallow state words drive that cost. Separating configuration could reduce mutable state width, but merely moving it into another RAM while still carrying every field through requests/results would not remove that transport. A useful probe must keep configuration indexed by actor slot and preserve startup, reset and debug visibility, with a measured read-port/latency cost. No area percentage follows from counting 172 bits.

Most snapshot activations update one neighbor record and a seen mask. A generic sparse state-write representation is therefore another candidate: narrow completion storage and RAM bank write enables could preserve unchanged fields without returning the whole machine. It requires transactionally consistent failure/phase state, storage-bank alignment and a changed result/write contract; it is not just a record-layout tweak. The present campaign first measures compact completion RAM and bounded gather visits. Retain signed 32-bit cluster IDs until their algorithmic range is established; the small current window alone is not such a bound.
