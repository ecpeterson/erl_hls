### Final route changes the size of the opportunity

Its actor-callback frequency means that an extra stage could cost much more than one clock per reduction window; the present singleton 346–348 budget does **not** cover that change. Inspect whether an existing executor boundary can absorb the cut before proposing another stage.

This is a broader, staged design proposal, not an implemented performance result. It offers a way to preserve completion latency while cutting the offending ownership dependencies. A substantial whole-application estimate still needs the shared-admission and executor-completion budgets; do not replace that missing evidence with the smallest observed period from another placement.

## Ownership and boundaries

Give the collector and actor independent activations. The collector owns per-producer contribution slots, arbitration, epoch/member validation, accumulator and completion ownership. The actor owns ordinary messages, phase/data, entry effects and completion callbacks. Neither may stall the other's state update by evaluating its current callback or fold. One contribution may commit per clock even while an ordinary output is blocked. Keep the existing protocol assertions and all key/member/frame checks.

Classify at the existing topology routers, into ordinary and contribution lanes, rather than adding a new classifier proc ahead of every receiver. There is already a router boundary and a bounded input holding slot: move their ownership, do not automatically add stages. Startup readiness is an ordinary message on the same status port as later reduction contributions, so classifying a whole status port as permanently contribution-only would be wrong. Use the reserved schema, and use inferred output schemas only to prune impossible branches. External input remains validated; unknown producers need the checked generic route.

Both lane classes preserve producer order internally. A producer can still be held behind its own earlier ordinary effect; splitting receiver storage does not permit reordering an ordered source stream. They have no shared atomic multi-send: an ordinary input held at this receiver must not block acceptance from separate available contribution lanes. Cross-class early folding is justified only by the asserted exclusive ownership, commutative reduction and no-overlapping-epoch contract. A contribution cannot become visible to actor code except through checked opening and completion. Normal actor messages remain FIFO-ordered. This obligation belongs in the existing compile-time protocol-verification follow-up.

## Bounded control protocol

- `open(key, members, initial)`: actor to collector. Validate against any early accumulated inputs. Never copy the live accumulator into actor state.
- `complete(key, value, failure)`: collector to actor, exactly once per opened epoch, after every required member. A failed reducer still drains its member obligations.
- `release(key)`: actor to collector after consuming completion. Keep the bank owned until release; a completed message in a handoff FIFO alone is not release.
- Sticky protocol failure and live progress remain independently observable through debug. Failure observation is asynchronous across this boundary; already committed effects are not retractable. Do not silently promise transactional failure or drop error detection.

Use bounded registered control crossings. Release and a successor open can be consecutive operations: either distinct one-entry channels or a two-entry ordered control FIFO must allow that schedule without the current depth-one FIFO's full/pop bubble. A mismatching next-epoch input while release is in flight must wait in its input slot; premature input to an incomplete collection remains an error. Every control message is keyed, and reset clears both endpoints and all handoffs together. Completion consumption and release enqueue form one committed actor transition; backpressure must not permit consuming twice or forgetting release. The actor retains an open/completion obligation for phase checks, not a stale copy of the live accumulator. Debug requests keep logical actor identity and reach the owner of each field; cross-owner snapshots must identify epochs rather than pretend to be atomic.

## Completion need not add a clock

The present unregistered-output collector has this observed leaf schedule:

| Edge | Current combined service | Proposed independent collector |
| --- | --- | --- |
| F | Final input updates the bank to complete | Final checked fold stores the completed result in the registered handoff |
| F+1 | Actor consumes bank completion | Actor consumes the handoff and executes the same completion callback |
| F+2 | Entry publishes the aggregate | Entry publishes the aggregate |

The handoff is written from the **next fold result**, replacing the existing completed-bank register boundary. Waiting until the following clock to notice completion and then enqueue it would add a clock at each tree level; reject that implementation. Retain collector ownership separately until the keyed release. Open/release latency can be hidden by the application's command/work interval, but this must be measured, especially for all-early input and zero-work fixtures. The eight-sheet diagnostic observes the first leaf contribution no earlier than 62 clocks after the command, and the first root contribution no earlier than 92. That suggests room for the one-clock open crossing here, but it is not a measurement of actual opening acceptance and does not cover all-early inputs. Instrument open/complete/release acceptance in the prototype. Remove the candidate A effect register when evaluating this design.

A further option is to stage opening validation inside the collector if its standalone membership/population-count path remains long. Freeze folding for that bounded validation transaction, retain arrivals in the input slots, then commit the validated bank before resuming; do not compute against a seen-mask snapshot while independently mutating it. This pays for an opening, not every contribution. The observed command-to-first-input margin motivates hiding it in this workload; all-early/zero-work cases still need an explicit latency measurement. This option fits the same cycle budget only if the complete replay confirms that hiding. It does not require more actor work to fill a global scheduler pipeline.

## Capacity and likely cost

Do not disguise this as free storage. Splitting seven root inputs and twelve leaf inputs may add held slots where one physical lane carries both classes; six leaf command lanes need no contribution copy. Twelve internal status lanes are mixed; conservatively allow the root external lane to be mixed until its schema restriction is checked. That bounds the additional holding storage at thirteen 128-bit frame slots (1,664 data bits), before justified field/lane pruning. Add seven bounded open/completion/release crossings; remove seven egress registers and avoid a second live accumulator in actor state. This is a storage budget, not a LUT prediction: FIFO mapping, arbitration and checks determine the mapped cost. The split targets timing and maintenance; measure area rather than promise it falls.

At 346.016 clocks, the split beats A's measured 350.772 clocks provided its routed period is no more than 1.374% worse. Moving classification, fold/error handling and actor dispatch into distinct cones should help, but layout and collector-open/population counting can become new limits.

## Registered-boundary prototype (2026-10-01)

This first implementation cuts cross-owner data dependencies without introducing new procs or pipeline stages. Direct and shared placements use the same `CollectionControl`/`CollectionBank` primitives. An actor retains its immutable opening descriptor; the bank owns partial progress. Opening/release commands cross a state register. A completed scalar result is copied into the callback, so releasing after consumption is safe. Sticky protocol faults return through committed status; callback effects already committed before validation are not retractable.

Shared ordinary admission and collection now have separate fair selectors. Contribution selection does not read mailbox occupancy or find a mailbox RAM slot. It preserves one fold per scheduler activation and allows a different producer's ordinary admission in that activation. No phi fragments are serialized or migrated. Actor and collector still share the enclosing XLS activation enable: blocked ordinary output can stall collection. This is a smaller stage toward the independent activation design, not its completion.

The executor experiment reserves six **unit-model scheduling cost units** at `_result_out:send` and adopts only the six rescheduled vertex-executor module bodies. It does not mean six nanoseconds, add stages, change FIFO depths or alter other procs. The original and replacement ports and two-stage structure must match. Isolated OOC synthesis improves 6.019 → 5.424 ns; that is not a prediction of routed whole-core improvement. All 8,460 recorded callback requests compare cycle-for-cycle across six executor pairs under stalls and reset.

The combined full replay returns all 128 rounds and 1,125 ordered corrections at 346.015748 mean clocks (316–617, population variance 4,947.921). It recovers the output-register penalty. The exact final generated sources match the measured sources. Both generated singleton output readiness cones exclude pending inputs/current ownership commands. Two/three-stage shared RTL, direct receiver RTL, all-mask generated tests, output-stall replay and zero-SCC structural checks pass. Route qualification still determines whether this prototype can be retained.

For snapshot collection, release must follow the last callback/entry that reads the retained source slots; completion delivery alone is insufficient. Either carry a lease through those reads or copy the small final value as this monoid implementation does. Do not apply the current automatic post-callback release to zero-copy snapshots. Preserve bounded successor banks and per-source writes as storage policies behind the ownership protocol.
