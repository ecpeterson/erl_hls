# Indexed snapshot area review

Status: the latest matched route passes the throughput threshold; final passive profiling and local qualification pass. The measured gain costs additional LUTs.

## What we chose, and what it cost

The first implementation reduced mean round gaps from 346 to 256.590551 clocks but increased synthesized LUTs from 154,564 to 268,496, exceeding device capacity. Shared controllers accounted for 105,105 of the 113,932 added LUTs. Actor transactions fell, but the added area concentrated in shared controllers. The comparisons below test particular controller representations; payload bit count alone does not price their accesses.

The original comments document behavioral requirements, and the code records the implementation choices. The motivations below are reconstructed from those requirements; they were not recorded as hardware-cost tradeoffs. We implemented these structures before a matched controller-level area screen.

- **Check every producer before choosing one.** The original `indexed_can_accept` explicitly aimed to prevent blocked banks from monopolizing arbitration. `indexed_select` therefore checked 19 or 22 independently addressed actor contexts per scheduler before accepting at most one input. Cached `indexed_inputs` kept decoded and raw frames aligned at their holding edge. This bought readiness-aware selection, but described parallel metadata lookups and duplicated decoded storage. For one accepted member per scheduler step, start with fair pick/check/retry: retain a blocked frame and advance arbitration. Measure blocked attempts per accepted member and acceptance rate at the required offered load. Add parallel readiness checks only if retries prevent that rate and a matched mapped comparison justifies their cost. The indexed producer-first bundle, and later the analogous scalar-reduction change, preserved the measured cohort’s complete output timeline. The passive scalar observer then counted 29,580 accepted contributions and no bank-readiness rejection. It counted 1,452 control-conflict waits, which the former bank-readiness check did not exclude. Parallel bank-readiness lookup therefore bought no observed avoidance in this cohort. If retry misses the required rate, separate bank-readiness rejections from control conflicts before adding parallel bank checks. Separately, a measured selection path can justify computing narrow predicates once per stored actor row. Neither case justifies repeating whole-context reads per producer without a mapped cost comparison.
- **Return a complete context from every transition.** `indexed_retire`, `indexed_commit` and `indexed_issue` composed retirement, admission and borrowing while preserving independent actors and complete failure states. Complete post-states were easy to compare and test. Each transition was expressed as selecting a context and replacing an array row; borrowing could read through earlier replacements. The optimized indexed context contained 1,055 bits per actor, although each operation reads only a subset. Unchanged frames and metadata entered the same feedback expressions as changed fields. Where several transitions update the same array in one clock, keep pure transitions as semantic references while committing field-local commands: each stored field keeps its own previous value unless its owner writes it. Choose storage from its simultaneous readers, writers and field lifetimes, not merely its aggregate bit count.
- **Reuse ordinary source dispatch for eligibility.** `indexed_classify` deliberately let actor callbacks determine postponement and failure. Calling `dispatch` preserved that authority without inventing another source interpretation, but dynamic opcodes at five frame contexts left unrelated handler dependencies available to synthesis. Their reserved-tag provenance was a temporal invariant, not an explicit restriction at the call. The alternative is a constant-op branch for each reserved tag, still calling ordinary dispatch and preserving payload, guard and failure checks.
- **Compose reserve and offer through whole-state APIs.** `indexed_push` reused independently checked `indexed_collection_core::reserve` and `offer`. Reservation constructed a bank array; offer selected from it again, although reservation already identified the bank. Carrying that scalar bank through both checked transitions avoids this representation round trip and commits once. This changes composition, not validation. Inspect optimized IR for the selection dependency; use matched mapping to measure its cost.

## Reusable design rules

- Price a service by simultaneous addresses, field accesses and guarantees, not stored bits. Moving work out of actors can introduce a more expensive shared metadata/control service; its port and dependency budget belongs in the initial design.
- Match speculative work to useful acceptance bandwidth. Select before expensive per-request work unless measured retry costs require broader readiness knowledge. Narrow predicates computed once per fixed storage row are a different trade from wide reads repeated per producer.
- Separate a clear semantic model from its hardware update interface. Keep complete-state transitions as references; emit narrow commands with explicit field ownership, conflict priority and forwarding. Compose operations through the selected bank or record rather than repeatedly reconstructing and reselecting a container.
- Carry established facts across internal boundaries. An internally constructed lease or known reserved tag should remain visible to the compiler. Express the precondition locally and retain checks at boundaries where the fact is not established; this is not permission to assume arbitrary protocol correctness.
- Assign each measurement one job. IR dependency walks check whether a proposed edge was removed; representative synthesis screens capacity; routed period times measured clocks decides throughput. Keep the original performance baseline as well as a fresh same-source control, so a regressed control cannot turn a loss into apparent success.

## What the measurements establish

Our first recovery estimate also failed: the r3 bundle reduced optimized IR nodes from 62,350 to 50,686 and synthesized FFs by 7,751, but increased LUTs to 270,670. The forecast of 40,000–60,000 fewer LUTs was not calibrated. Conversely, the later dispatch/writeback variant increased the selector-width proxy while reducing mapped area. These proxies did not rank the candidates reliably.

The first matched isolated-controller improvement combines reserved-tag dispatch and field-local writes: 45,496 to 38,878 LUTs (14.5%), 15,930 to 14,849 FFs, and an unplaced period estimate of 13.464 to 10.237 ns. The complete replay is unchanged. This supports the combination, not separate attribution to either change or extrapolation from an isolated controller to device fit.

The last unsuccessful best route, `selected-tag-r2`, used 215,033 LUTs at 12.179 ns: a 3.125016-µs mean-round proxy, 5.18% worse than the original 2.971102 µs. The combined follow-up, `router-head-r1/full-application-r1`, now routes at 10.585 ns with 213,580 LUTs, 106,500 FFs and 48 BRAM36s. Its unchanged 256.590551-clock mean gives 2.716011 µs: 8.59% less round time, or 9.39% greater round rate, than the original. The trade is 38.92% more LUTs and 18 fewer BRAM36s. Hold, pulse-width, routing and internal coverage checks pass. This is one matched setup-derived comparison, not closure at the requested clock or a long-run stability result; it establishes a throughput win, not an area win. The bundle does not isolate each cut's contribution.

The remaining routed leader is admission-to-frame retention: a pending producer opcode feeds eligibility/arbitration, selected-frame classification and an actor’s deferred payload write. Of the top 50 paths, 27 end in deferred payloads and ten in representative frames; the former issue/writeback family has disappeared from this set. The leader has 3.015 ns logic and 7.347 ns routing delay before clock effects. This locates the next bottleneck, without attributing each removed path to an individual change.

The fresh ordinary-mailbox control takes the same 346 clocks but routes at 9.819 ns with 173,001 LUTs and 72 BRAM36s, yielding 3.397374 µs. It includes the new gather-source representation and current compiler; it is not the unchanged pre-feature source. Gather progress widens the ordinary ActorState from 621 to 699 bits, accounting for all six additional BRAM36s; the largest LUT increases are in request FIFOs and executors. This is a cost of the combined source/compiler/backend revision, not an isolated measurement of generic timing cuts. Comparing indexed against that control gives a 20.06% round-time reduction, but the original 8.59% comparison remains the campaign acceptance test. A smaller earlier variant demonstrates why area alone is insufficient: retirement preclassification reduced routed LUTs from 216,704 to 212,715 while worsening the period from 12.213 to 14.168 ns, despite an improved unplaced estimate.

Before topology-wide integration, map baseline and candidate controllers at the intended actor-row count and producer fan-in; here that means the 19- and 22-producer shapes. Record concurrent readers, field writers and same-row conflict priority beside that comparison. Set the controller area allowance before seeing the result; exceeding it triggers redesign before a complete build. Here the baseline left 75,836 LUTs of raw capacity. Preregister a routing allowance H and require controller increments, weighted by each shape’s instance count, to stay below 75,836 − H LUTs at the same component boundary, assuming unchanged remaining logic. Even H = 0 allows only 12,639 extra LUTs per controller on average. The first complete candidate added about 17,518 per controller including children. Reject a representative-controller result above that allowance before integrating all rows. We did not run that screen initially; the later full-chip excess does not establish what it would have predicted, and embedding changes constant propagation. Passing this screen authorizes the full experiment, not a claim of device fit or routed throughput. At the unchanged mean of 256.590551 clocks, acceptance requires a routed setup-derived period below 11.579156 ns.

The reusable [native report workflow](../experiments/07-openxc7/timing_chains/README.md) now accepts a preregistered synthesis budget with fixed row counts, producer fan-in, component boundary, tool, target and constraints. It separates controller-owned logic from children and requires pinned evidence. Historical runs without that registration remain numerical diagnostics, not retrospectively passing gates.

For this controller, the concrete access capacity is up to one retirement, one admission and one borrow per committing scheduler step. Retirement classifies against the returning machine; admission needs no old saved-frame bytes; borrowing changes neither frames nor bank identity/membership. Retirement cannot share an actor with admission or issue, while admission and borrow can share one: borrowing must forward current kernel failure and preserve the other bank’s updates, while its selected sealed bank’s identity remains committed.
